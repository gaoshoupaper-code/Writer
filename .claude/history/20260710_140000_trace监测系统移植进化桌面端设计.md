# Trace 监测系统移植到进化桌面端 — 设计方案

## 架构方向（待确认）

将 evolution web 端（`evolution/frontend/`）的 trace 可视化组件层完整移植到 evolution 桌面端（`evolution/desktop/src/`），适配三处差异层（API 客户端、SSE 流机制、CSS 变量体系），同时在监测大盘新增创作/进化双 tab，并补齐后端 active-runs 端点的 run_purpose 数据。

## 识别到的技术断层

### 断层 1：CSS 变量体系不兼容（最大适配成本）

两端变量命名完全不同：

| web 端变量 | 含义 | 桌面端对应 |
|------------|------|-----------|
| `--text` | 主文字色 | `--ink` |
| `--text-dim` | 次要文字色 | `--muted` |
| `--text-mute` | 更弱文字色 | 无直接对应 |
| `--surface` | 卡片面 | `--panel-solid` |
| `--surface-2` | 次级面 | `--panel-soft` |
| `--surface-3` | 三级面 | 无直接对应 |
| `--border` | 边框 | `--line-strong` |
| `--border-soft` | 弱边框 | `--line` |
| `--accent` | 强调色 | `--teal` |
| `--accent-soft` | 强调弱底 | 无直接对应 |
| `--running` | 运行态色 | 无直接对应 |
| `--completed` | 完成态色 | 无直接对应 |
| `--failed` | 失败态色 | `--danger` |
| `--node-agent/llm/tool/...` | 节点类型色 | 无直接对应 |
| `--shadow-elevated` | 阴影 | `--shadow` / `--shadow-soft` |
| `--font-mono` | 等宽字体 | 需确认 |

**影响**：web 端 trace CSS（约 800 行，738-1550）全部引用上述变量。直接复制到桌面端会导致样式全部失效。

### 断层 2：SSE 命名事件解析缺失

trace SSE 帧格式（`sse_stream.py` 第 90-104 行确认）：
```
data: {TraceLogEvent json}     ← 默认事件（逐条增量）
event: snapshot\ndata: {...}   ← run 状态校准
event: end\ndata: {}           ← 终态信号
event: error\ndata: {...}      ← 错误降级
```

桌面端 `evoSseStream`（stream.ts）只解析 `data:` 行，丢弃 `event:` 名。
→ 需新建 `evoTraceStream` 解析完整 SSE 帧。

### 断层 3：API 层差异

web 端 `monitor-api.ts` 用原生 `fetch` 直连。
桌面端用 `evoFetch`（Rust 中继 + `/evolution-api` 前缀）。
→ `useTraceStream` 内的 API 调用需替换为桌面端已有函数。

## 已确认架构决策

- **S1：CSS 变量适配 = 变量桥接 + 节点色独立声明**——桌面端 `:root` 追加 web 端变量别名（`--text: var(--ink)` 等），语义色（`--node-*`/`--running`/`--completed`）从 web 端 `@theme` 复制色值独立声明。CSS 和组件零改动。
- **S2：useTraceStream 适配 = 改 hook 内部**——直接用桌面端已有 API（`getTraceDetail`/`getActiveRuns`），替换 `new EventSource` 为 `evoTraceStream`，不抽中间层。
- **S3：页面结构 = 自建页面壳 + 子组件复用**——不移植 TracePanel 组件，自建 `trace-detail.tsx` 薄壳管理 tab/高亮/抽屉状态，复用 Timeline/Drawer/TokenChart/Icon 四个纯展示子组件。

## 已确认数据契约决策

- **S4：evoTraceStream 帧格式 = `{ event, data }` 统一结构**——`TraceSseFrame` 联合类型，`event` 字段为 `"data"|"snapshot"|"end"|"error"`，与 SSE 协议 `event:`/`data:` 一一对齐。
- **S5：isTraceActive = 内联实现**——hook 内部 `(await getActiveRuns()).some(r => r.trace_id === traceId)`，不抽函数。
- **S6：监测大盘 tab = 全量拉取 + 前端过滤**——`getActiveRuns()` 拉全量，前端按 tab 选择的 `run_purpose` 集合 `.filter()`。5s 轮询不变，tab 切换零延迟。

## 已确认 WBS 决策

- **S7：旧 trace CSS = 本次不清理**——只追加新样式，旧样式留作后续清理。在文档中标注备忘。
- **S8：WBS 划分 = 按依赖层自底向上（4 Phase）**——每层可独立编译验证。
