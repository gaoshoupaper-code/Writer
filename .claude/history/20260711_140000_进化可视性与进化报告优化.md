# 进化可视性与进化报告优化

## 核心诉求（待确认）

在进化桌面端，用户**审查一次进化时看不到"到底改了什么、为什么这么改、证据在哪"**，导致无法判断这次进化是否该发布。

现状诊断（已查证代码）：
- 后端已产出全部数据：评估报告（findings 含 evidence）、design_doc.md（含结构化 changes + reason）、change_log.md（含落地记录 + 校验）、version_changes（intent + diff）。
- 桌面端 `evolve.tsx` 只展示状态/分数/SSE 流水/一段原始 JSON dump，**没接通** design_doc/change_log/version_changes 这三根管子。
- 进化 trace 与普通创作 trace 在详情页零差异化。

## 已确认决策

### R1 — 审查主轴：design_doc（改了什么 + 为什么改）
用户审查一次进化时，核心要看的不是三段因果链全展开，也不仅是结果 diff，而是 **design_doc 里的改动清单 + 理由**：这次动了哪些东西、理由是否成立。
- 评估 finding 作为**支撑证据**呈现（不是主轴，但必须可查）。
- change_log（落地结果）和版本 diff 作为**辅助确认**：方案是否真的落地了。

### R2 — 证据定义：引用评估 finding
"证据" = 每个改动必须**引用评估报告里具体的 finding**（哪条诊断、dimension、severity、evidence）。
- 含义："这次改是因为评估发现了这个问题"。
- **需新增硬性约束**：Agent 产出的每个 change 必须带 `evidence_ref` 字段，指向具体 finding。当前 design_doc schema 只有 `reason`（自由文本），不强制引用。

### R3 — 审查入口：专门审查视图
session 进入 `pending_review` 后，点"审查"打开一个全屏/大抽屉的**审查报告视图**，平铺展示改动清单 + 理由 + 证据 + 落地结果 + 分数对比，底部放发布/丢弃按钮。
- 不在 evolve.tsx 详情区角落挤，信息要舒展。
- 需要新建审查组件（路由或大抽屉，二选一在设计阶段定）。

### R4 — finding 加稳定 id（连锁：要动评估 Agent）
评估 Agent 产出的 findings 数组，每条加稳定 `id`（如 `f01`/`f02`）。design_doc 的 `evidence_ref` 指向这个 id。
- **连锁影响**：评估 Agent 的 schema 和 prompt 要改，让它在产出 finding 时带 id。
- 这是这次需求里**唯一要动评估端**的地方（其余都集中在进化端 + 桌面端）。

### R5 — 范围边界：只做发布前审查
本次**只做 pending_review 阶段的审查视图**，不接 `/api/versions`、不做发布后的历史版本 diff。
- 发布后的历史追溯（看旧版本改过什么）以后再说，不纳入本次。
- 审查视图数据源 = design_doc + change_log + 评估 finding + 分数对比，全部 session 级。

### R6 — 证据缺失：硬拦截
schema 硬校验：design_doc 的每个 change，`evidence_ref` 缺失 → `write_design_doc` 直接报错，阻断流程，Agent 必须重填。
- 含义：进化质量优先，宁让 Agent 多跑也不放过没证据的改动。
- 校验点在 `write_design_doc` 工具（plan 子代理），和 R4 的 finding_id 存在性校验一并做。

### R8 — 数据残缺：拒绝渲染
session 跑失败/中断、没产出完整 design_doc 或 change_log 时，审查视图**不渲染报告区**，只显示：
- session 状态（failed / 中断点）
- 错误日志（SSE 已有）
- 明确提示"此 session 无完整报告，无法审查"
- 不勉强凑展示，残缺报告只会误导审查者。
