# 进化端 Agent 执行显示优化 — 设计

## 设计变更摘要（相对需求文档的简化）

> **重大架构简化**：勘察发现 trace SSE 本身就推框架事件（trace 详情页能显示 LLM 节点）。
> 评估/进化页**抛弃 eval/evolve 专用 SSE**，**统一复用 useTraceStream + trace SSE**。
>
> **影响**：需求文档中的 F4（解锁 LLM 框架事件 SSE 推送 + 节流）**取消**——trace SSE 已具备。
> 其余 F1-F6 保留。

---

## 架构快照

### 旧（割裂两套 SSE）

```
eval/evolve SSE ──> liveLogs ──> 平铺日志（评估/进化页）
trace SSE ──> useTraceStream ──> 节点树（trace 详情页独占）
```

### 新（统一 trace SSE）

```
trace SSE ──> useTraceStream(trace_id_self)
              └─> ExecutionFlowPanel（评估/进化页内嵌）
                  ├─ FlowToolbar（状态/步骤数/总耗时/停止/跳trace详情）
                  ├─ Tabs（执行流 | 报告）
                  │   ├─ StepList（顶层节点 + subagent 折叠）
                  │   └─ ReportPanel（评估报告 / 进化会话详情）
                  └─ StepDrawer（右侧抽屉，复用 TraceChainDrawer 子组件）
```

### 数据真源

**单一真源：trace nodes（来自 TraceDetailLite）**。
- agent emit_step 业务事件 → trace 投影成 business node（kind=agent/tool）
- 框架 LLM/tool 事件 → trace 投影成 framework node（kind=llm/tool）
- subagent 调用 → trace 投影成 depth=1 的 agent 节点（`parent_node_id='run'`）
- 一切节点统一为 `TraceNode` schema（`contracts/trace/__init__.py:120-142`）

**不再有"两套数据合并"问题**。

## 组件架构（路径 B：新建独立 ExecutionFlow 组件体系）

```
pages/evaluation.tsx          pages/evolve.tsx
       │                            │
       └────────┬───────────────────┘
                ▼
       <ExecutionFlowPanel>           容器：接受 session + run_purpose props
        ├─ <FlowToolbar>              顶部工具栏
        ├─ <Tabs value tab onChange>  自写 Tab 容器
        │   ├─ <StepList>             「执行流」tab
        │   │   ├─ <StepItem>         agent / 顶层 error 节点
        │   │   ├─ <StepItem>         subagent（可折叠）
        │   │   │   └─ <StepItem>×    subagent 子节点（展开后渲染）
        │   │   └─ (并行组横向布局)
        │   └─ <ReportPanel>          「报告」tab（按 run_purpose 渲染评估报告/进化会话详情）
        └─ <StepDrawer>               右侧抽屉
            └─ (复用 trace 抽屉子组件)
```

### 关键组件职责

#### `ExecutionFlowPanel`
- props：`session`、`run_purpose: 'eval' | 'evolve'`
- 内部状态：active tab（执行流/报告）、active node（抽屉打开）
- 调用 `useExecutionFlow(session.trace_id_self)` 拿 nodes + run
- run 状态终态时自动切到「报告」tab

#### `useExecutionFlow(traceId)`
- 包裹 `useTraceStream(traceId)`
- 返回 `{ nodes, run, isActive }`
- `isActive` 判断：run.status === 'running' && useTraceStream 内部 active
- 若 `traceId` 为 null：返回空数据 + `isActive: false`

#### `StepList`
- 输入：`nodes: TraceNode[]`、`collapsedAgents: Set<string>`、`onSelect`、`onToggleAgent`
- 过滤 `parent_node_id === 'run'` 的节点（顶层）+ 处理 subagent 折叠
- 顶层节点按 `started_at` 排序
- 并行组（`parallel_group_id` 相同）横向分组（复用 trace 详情页逻辑）

#### `StepItem`
- props：`node`、`active`、`expanded`、`childCount`、`onSelect`、`onToggle`
- 显示：状态图标 + 标题（`nodeBodyLabel(node)` + tool 中文字典插值）+ 状态文字 + 耗时（`formatDuration` + `durationColorClass`）+ 折叠箭头
- 标题来源：复用 `nodeBodyLabel`（trace 详情页已有，对 agent/llm/tool 都有处理）
- 失败节点：红色 + 错误摘要直接显示（`node.chain_summary`）

#### `StepDrawer`
- props：`node`、`onClose`
- 内部懒加载（同 trace 详情页抽屉）：`getTraceEvents` + `getTraceContext`
- 内容渲染：复用 `TraceChainDrawer` 抽出来的子组件
  - LLM 节点 → `DrawerLLMContent`（context segments）
  - Tool 节点 → `DrawerToolContent`（tool_args + tool_output）
  - Error 节点 → `DrawerErrorContent`（错误堆栈）
  - Todo 节点 → `DrawerTodoContent`
- **前提**：把 `TraceChainDrawer` 的渲染子组件**抽出为独立文件**（`trace/drawer/DrawerLLMContent.tsx` 等），让 `TraceChainDrawer` 和 `StepDrawer` 都引用。

#### `ReportPanel`（按 run_purpose 分流）
- `run_purpose === 'eval'`：渲染现有 `EvalReport`（迁移进来）
- `run_purpose === 'evolve'`：渲染重做的进化会话详情卡片

#### `toolLabels.ts`
- tool 名 → 中文 label 字典 + 动态插值
- 未命中字典：回退到 `node.tool_name` 原值
- `node.chain_summary` 已是后端算好的摘要（projector 中 `build_tool_summary` / `llm_summary`），**StepItem 直接用，不走字典**
- 字典仅用于"无 chain_summary 时的兜底标题"

## 数据模型

### TraceNode 字段使用（已存在，不改）

执行流视图消费 TraceNode 的字段：

| 字段 | 用途 |
|---|---|
| `node_id` | React key + 折叠状态追踪 |
| `parent_node_id` | 判断顶层（== 'run'）+ 折叠判断 |
| `kind` | 图标 + 标题渲染（agent/llm/tool/error/skill/todo） |
| `label` / `agent_name` / `tool_name` / `model_name` | 标题来源（`nodeBodyLabel`） |
| `status` | 状态图标 + 着色 |
| `chain_summary` | 节点摘要文字（一行话） |
| `duration_ms` | 耗时显示 |
| `started_at` | 排序 |
| `raw_event_ids` | 抽屉懒加载 event_id 列表 |
| `context_anchor_id` / `output_context_anchor_id` | 抽屉懒加载 context |
| `depth` | subagent 缩进（depth=1） |
| `error` | 失败节点直接显示 |
| `parallel_group_id` | 并行组横向布局 |

## 接口契约

### 后端：trace_id_self 反查

**修改**：`app/eval_agent/repo.py:list_sessions`、`app/evolve/db.py:list_sessions`、两端的 `get_session`。

**反查函数（建议放 `app/trace/recorder.py` 或新建 `app/trace/lookup.py`）**：
```python
def find_trace_id_by_session(session_id: str, run_purpose: str) -> str | None:
    """按 session_id 反查自观测 trace_id。
    
    走 runs.thread_id 反查（持久化通道，进程重启不丢）。
    """
    row = db.query_one(
        """SELECT trace_id FROM runs
           WHERE thread_id = ? AND run_purpose = ?
           ORDER BY started_at DESC LIMIT 1""",
        (session_id, run_purpose),
    )
    return row["trace_id"] if row else None
```

**接口响应扩展**（不新增端点，原端点加字段）：
- `GET /api/eval-agent/sessions` 和 `GET /api/eval-agent/sessions/{id}` 的响应每条 session 增加 `trace_id_self: string | null`。
- `GET /api/evolve/sessions` 和 `GET /api/evolve/sessions/{id}` 同样增加 `trace_id_self`。

**性能**（N+1 处理）：
- `list_sessions` 默认 limit=50，对每个 session 调一次反查 = 50 次 SQL。
- 优化方案：**一次性 IN 查询**——先取 session_id 列表，再一次性查：
  ```sql
  SELECT trace_id, thread_id FROM runs
  WHERE thread_id IN (?, ?, ...) AND run_purpose = ?
  ```
  构造 `dict[thread_id → trace_id]`，再回填到每个 session。
- SQLite 的 IN 查询支持到 999 个参数，limit=50 远未到上限。

### 前端：useTraceStream 调用

直接复用现有 hook，**零改动**：
```ts
const { nodes, run, isActive } = useTraceStream(session.trace_id_self);
```

## 边缘场景与降级

| 场景 | 处理 |
|---|---|
| `trace_id_self` 为 null（trace 未创建） | ExecutionFlowPanel 显示"等待 Agent 启动…"，retry 3 次后降级为只显示状态徽章 |
| trace 详情加载失败 | 显示加载错误 + 重试按钮 |
| SSE 断连 | useTraceStream 已有重连机制（依赖现有实现） |
| session 运行中切走再回来 | 组件挂载 → getTraceDetail 拉历史 → useTraceStream 自动接 SSE 增量 |
| 节点 > 50 条 | 后续可加虚拟列表，本期先全量渲染（评估/进化一次 run 节点数通常 < 30） |
| 并行 tool_calls | 复用 trace 详情页 parallelGroups 逻辑，横向分组 |
