# 进化功能改造需求

## 核心诉求（一句话理解，待用户确认）

> 用户想让进化 Agent「更聪明、更听话、跑得动」三件事一起做：把进化历史提升为独立 tab（位置夹在蓝图和对话之间），放开 Agent 步数上限到 200 让它能跑完整流程，并把"记忆"这套东西在蓝图认知和工具能力上都补齐——让 Agent 真正"知道有记忆这回事"且"能改记忆要素"。

## § 实现风险清单

| # | 风险点 | 在哪塌 | 建议验证方式 |
|---|---|---|---|
| R1 | **历史双源**：新 tab 显示历史，但 workbench 左栏也轮询同一个 `getEvolveSessions`——两处独立轮询会重复请求、状态不同步（A 处刷新 B 处没刷） | 桌面端进化页：新 tab + workbench 左栏同时存在时 | design 阶段定方案：① workbench 左栏历史移除（只留新 tab）vs ② 共享 SWR/缓存 vs ③ 两处都保留但接受重复轮询 |
| R2 | **round 函数无 GraphRecursionError 兜底**：放开到 200 后，如果对话式进化（converse round）触顶 200，异常会直接抛给 API 层，session 卡在 running 状态无法收敛 | `agent.py` run_inspect_round / run_converse_round / run_finalize_round | design 阶段评估：是否把 `run_evolve_session:261-277` 的 try/except GraphRecursionError 兜底同步到 3 个 round |
| R3 | **200 步 token 成本**：每步至少 1 次 LLM 调用，200 步 = 上限 200 次 LLM 调用。如果 Agent 真跑满，token 成本可能显著上升 | evolution 服务运行成本 | design 阶段评估：是否需要加 trace 埋点观测"实际跑了几步"，或加 token 累计阈值告警 |
| R4 | **蓝图 token 膨胀**：把记忆认知从动态注入（有才有）改为固化主结构（永远有），蓝图 system prompt 每次都带这段。NWM 6 要素表 + 协同说明 + 软约束约 300-500 token | Agent 每次 ainvoke 的 system prompt | design 阶段确认：固化 vs 保留条件注入的 token 成本差，老版本（无 NWM）是否还要兼容空态 |
