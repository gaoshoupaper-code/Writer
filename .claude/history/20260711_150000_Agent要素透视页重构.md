# Agent 要素透视页重构 — 需求基准

## 核心诉求（待用户确认）

重构 evolution 桌面端 `harness`（Agent 要素）页，让产品负责人选一个版本时能一眼看懂两件事：

1. **这个版本的 Agent 是怎么搭的** —— 要素按类型（Prompt / Skills / Middleware）显性分开，Middleware 按 6 个生命周期 hook 结构化呈现，而不是现在这种"挤在 Agent 卡片里小节平铺、middleware 只剩类名+hook 两个字符串"的贫展示。
2. **这个版本相比上一版改了什么** —— 利用后端已就绪但前端完全没接的 `version_changes` 数据（结构化 diff + design_doc 改动意图），显式标注本版本升级了哪些方面。

## 现状诊断（事实链）

| 诉求 | 数据层 | 当前 UI | 断层 |
|---|---|---|---|
| 直观看版本要素 | ✅ ElementsView 有三类 | ⚠️ 平铺、prompt 截断 500 字、middleware 只剩两列文字 | 展示贫瘠 |
| 各类型要素分开 | ✅ 三类已分 | ⚠️ 靠 h5 小标题弱区分，挤在 Agent 卡片内 | 分类不够显性 |
| 标注版本升级内容 | ✅ version_changes 表有完整 diff + intent，versions_api.py:146 已挂响应 | ❌ 前端 api.ts 未定义该字段，harness.tsx 只显示 40 字 change_summary | 数据现成但前端没接 |
| Middleware 标生命周期 | ✅ 有 hook(6种)/group/params/source_path | ⚠️ hook 当字符串标签平铺，无生命周期结构 | 语义未呈现 |

## 关键技术事实

- **页面文件**：`evolution/desktop/src/pages/harness.tsx`（唯一展示要素的页面，163 行）
- **前端数据结构**：`evolution/desktop/src/lib/api.ts:574-593`（AgentElementView / ElementsView）
- **后端要素投影**：`evolution/app/versioning/elements_api.py`（build_elements_view）
- **生命周期（hook）六格**：`evolution/app/harness_config/config.py:41-48` VALID_HOOKS = before_agent / before_model / wrap_model_call / after_model / wrap_tool_call / after_agent
- **版本升级数据**：
  - `version_changes` 表（db.py:285）：agent 级 diff_json（prompt/skills/processors 三要素 diff）+ 版本级 intent_json（design_doc 改动意图）
  - 已通过 `versions_api.py:146` 挂到 `GET /api/versions/{version}` 响应的 `changes` 字段
  - `config_diff.py`：三要素 diff 算法（prompt 行级 / skills 集合差 / processors added/removed/modified）
  - `version_changes_repo.get_changes(version)` → `{agents:[{agent,diff}], intent:[...]}`
- **前端当前完全没消费 changes 字段**（api.ts 无定义、harness.tsx 无渲染）

## 已确认决策（第 1 轮）

| # | 决策 | 选择 | 影响 |
|---|---|---|---|
| D1 | 升级标注数据来源 | **客观 diff 为主 + 主观意图补充** | 前端需新增对 `version_changes` 的 `diff_json`（prompt/skills/processors 三要素 diff）+ `intent_json`（改动意图列表）的渲染 |
| D2 | 要素分类信息架构 | **按要素类型分组（Tab 切换）** | 视图主体从"按 Agent 卡片"改为"Prompt / Skills / Middleware 三 Tab"，旧 D4 方案 |
| D3 | Middleware 生命周期展示 | **生命周期流水线图（泳道）** | 6 个 hook 为横向节点，middleware 挂在对应阶段下方；开发量最大 |
| D4 | 升级总览位置 | **顶部升级总览条 + Tab 内就近高亮** | 版本选择器下方新增总览区：列所有改动 + design_doc 意图摘要；各 Tab 内就近高亮改动项 |
| D5 | Agent 归属标注 | **每条要素标 Agent 徽章** | 每条 prompt/skill/middleware 旁加小徽章（meta/故事构建/...），泳道节点也标 |
| D6 | Prompt diff 共存 | **默认全文 + 可切"显示 diff"** | Prompt Tab 默认全文，顶部开关切换 Git diff 风格红绿高亮 |
| D7 | 首版本处理 | **显示"初始版本"占位** | 总览条始终在，首版本时显示"初始版本，无升级对比"提示 |
| D8 | 泳道图行维度 | **每个 Agent 一条泳道** | 纵向按 agent 分泳道（meta + 各 subagent），横向 6 个 hook 阶段；middleware 落在「agent × hook」格子 |
| D9 | diff 语义色 | **沿用 Git diff 惯例色** | 新增=绿、删除=红、修改=黄/橙 |
| D10 | 版本对比范围 | **只看 vs 直接父版本** | 后端 version_changes 已存 v(parent)→v(new)，无需改后端；不改任意两版本对比 |
| D11 | 泳道图交互 | **可点击展开详情 + 懒加载源码** | 点击 middleware 节点 → 展开 params/class_name + 「查看源码」折叠块（GET /source 懒加载） |
| D12 | 默认首屏 Tab | **Prompt** | 首屏默认 Prompt Tab，展示 Agent 系统提示词 |

| D13 | Skills/MW diff 高亮 | **认可建议方案** | Skills：新增路径绿底/删除路径红底；Middleware 节点着语义色（绿/红/黄），modified 展开 class/params 新旧对比 |
