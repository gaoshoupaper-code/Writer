# 进化端数据集链路重构 — 设计文档

## 架构方向（待确认）

**核心洞察**：golden 已被 git 跟踪（`git ls-files` 证实），entrypoint seed 覆盖机制正是"git 为权威源"的正确实现。真正的 bug 是运行时 `promote_to_golden` 写 golden 目录（与只读矛盾）。方案重点不是"大改存储架构"，而是：
1. **让 golden 运行时只读**（禁掉运行时写 golden 的路径）
2. **加固数据源拓扑**（消除 volume 覆盖 golden 的隐患）
3. **桌面端加刷新 + 错误不吞**

## 存储拓扑分析（已查实）

```
当前 Docker 拓扑：
/app/evolution/data/  ← evolution_data volume（整个 data 挂卷）
  ├─ evalset/
  │   ├─ golden/   ← 被 volume 覆盖 → entrypoint 从 /app/evalset_seed/golden 恢复（= git 版本）
  │   └─ growing/  ← volume 里的运行时数据，OK
  └─ evolution.db  ← volume，OK

镜像内（volume 外）：
/app/evalset_seed/golden/  ← Dockerfile:73 COPY 进来，= git 跟踪的 golden 内容
```

**问题**：golden 在 volume 内，每次启动靠 entrypoint 覆盖恢复。虽然能工作，但"golden 可被运行时写入"这个能力存在一天，数据丢失风险就存在一天。

## 架构快照（第 1 轮 ✅ 确认）

### 三大决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| golden 只读策略 | **禁掉运行时 promote** | golden 完全只读，变更只能 git commit + rebuild。零数据丢失风险，架构最简单 |
| golden 存储位置 | **保留现状 + entrypoint 覆盖** | golden 仍在 volume 内，每次启动从 seed 恢复（= git 版本）。改动最小，entrypoint 机制本身正确 |
| 错误处理 | **前端区分错误状态** | 服务端正常返回错误码，前端区分「无数据」vs「加载失败」，加载失败显示重试按钮 |

### 重构后的数据流

```
golden 变更路径（唯一合法）：
  git commit (改 evolution/data/evalset/golden/) → rebuild 镜像 →
  entrypoint 从 /app/evalset_seed/golden 覆盖 → volume 内 golden = git 版本

growing 变更路径（不变）：
  promote 闸门 accept → 写 volume 内 growing 目录 + dataset_meta

运行时 promote（growing→golden）：禁用（返回 403/410）
```

## 桌面端交互契约（第 3 轮 ✅ 确认）

### 刷新机制：页面头部全局刷新按钮
- `dataset.tsx` 页面头部（标题右侧）加刷新按钮（`lucide-react` 的 `RefreshCw` 图标）
- 父组件用受控 Tabs（`value` + `onValueChange`）记录当前激活 Tab
- 父组件维护 `refreshSignal: number` state，点击刷新 → `setRefreshSignal(n => n+1)`
- 通过 prop 把 `refreshSignal` 传给各 Tab 子组件
- 子组件 `useEffect(() => { refresh(); }, [refreshSignal])` 监听变化触发刷新
- **天然只刷当前 Tab**：Radix 卸载非激活 Tab，只有挂载的子组件响应

### 错误状态三态
每个 Tab 的列表数据增加 `error: string | null` state（区别于现有 `loading`/空列表）：

| 状态 | 显示 | 触发条件 |
|---|---|---|
| loading | `page-loading`（现有） | 首次加载 |
| error | **错误卡片**（⚠ 图标 + "加载失败" + 错误信息 + [重试]按钮） | 请求失败（不再 `.catch(() => 空列表)`） |
| 空（正常） | `monitor-empty`（现有，"暂无 case"） | 请求成功但列表为空 |
| 有数据 | 表格（现有） | 请求成功且有 case |

- **重试按钮**点击 → 调 `refresh()`
- 移除现有的 `.catch(() => ({cases:[],total:0}))` 静默吞错（GoldenTab:24 / GrowingTab:23）

### revision 信息条失败占位
- GoldenTab 的 revision 拉取失败（当前 `.catch(()=>null)`）改为：`revision` 为 null 时仍渲染信息条，显示"⚠ revision 信息加载失败"而非整个消失

## 技术断层与解法

### 断层：父组件触发子组件刷新
**问题**：Radix Tabs 卸载非激活 Tab，页面头部刷新按钮在父组件，需触发当前激活子组件的 `refresh()`。
**解法**：受控 Tabs + `refreshSignal` prop（见上）。React 经典命令式触发模式，已验证 Radix 原生支持受控（`tabs.tsx` 直接转发 `TabsPrimitive.Root`）。
