见 `20260709_100000_积分制度与账号管理.md`（已 confirmed，28 个决策点 D1-D28）。

## 架构决策（已确认）

### AD1 ✅ 积分数据归属 = 全局 executor 主库
- 新建 credits 相关表在 executor 主 SQLite（`executor/app/platform/core/db/__init__.py` 的 schema）。
- 余额、预扣冻结、流水全部全局存储。
- 理由：积分是全局资源（管理员发放、跨用户统计、邀请码到账），不属于用户分库的创作数据。

### AD2 ✅ 计费 hook = 独立 CreditsMiddleware
- 新建 `CreditsMiddleware`，与 `TraceMiddleware` 并列挂在 agent 装配链上。
- 职责：逐次拦截 model_call → 提取 usage（复用 `_usage_payload` 逻辑）→ 折算标准 token（D7 三档权重）→ 累加消耗 → 检查余额（D27 强停线）。
- 与 TraceMiddleware 解耦：TraceMiddleware 管"记录"，CreditsMiddleware 管"计费"。
- 创作结束时，从 CreditsMiddleware 累加器汇总本次创作总消耗 → 落一条流水（D23）→ 结算预扣（D4 多退少补）。

#### AD2 详细：装配链集成方式（代码验证 2026-07-09）

**注入模式（复用 TraceMiddleware 的 T2 模式）**：
```
RuntimeContext 新增字段：
  credits_middleware_cls: object | None = None  # CreditsMiddleware 类，执行端注入
  credits_recorder: object | None = None         # CreditsService 实例（管余额/预扣/流水）
```

**包内挂载点**（`evolution/harnesses/current/__init__.py`）：
- meta agent：在 `:142-145`（TraceMiddleware 插入处）旁边，加 CreditsMiddleware 插入。
- subagent：在 `:162-165`（middleware_factory 内）旁边，同样加 CreditsMiddleware。

**执行端构建 ctx 处**（`executor/app/domains/writing/agent.py:147-157` 的 `_assemble_via_package`）：
```python
ctx = RuntimeContext(
    ...,
    credits_middleware_cls=CreditsMiddleware,  # 新增
    credits_recorder=self.credits_service,      # 新增
)
```

⚠️ **关键约束**：CreditsMiddleware 需要在**每个 LLM 调用后**检查余额并可能触发强停。
中间件的 `awrap_model_call` 是"包住整个 model 调用"的——handler 执行完模型调用后，
response 里含 usage。CreditsMiddleware 在 handler 返回后提取 usage、累加、检查余额。
若需强停，抛出特定异常（如 `CreditExhaustedError`）中断 agent 执行。

⚠️ **谁不应该扣分？**：A/B 测试（`ab_endpoint.py`）、管理员操作、进化端评估——
这些不走用户创作路径，CreditsMiddleware 通过 ctx.credits_recorder=None 来跳过（与 TraceMiddleware 同样的 None 跳过逻辑）。

### AD3 ✅ 进化端→executor 调用 = SSO cookie + admin API 权限重构
- 进化端管理页请求带 SSO session cookie → 经 evolution FastAPI 后端代理转发到 executor `/api/admin/*`。
- executor admin API 统一要求 `is_super_admin=1`（D28）。
- 身份+权限都在 executor 侧校验。
- ⚠️ **待确认 Q7**：evolution 后端代理转发 vs 前端直调 executor？

### AD4 ✅ 数据模型 = 接受（Q4 确认）
- 4 张表/字段：users 扩展（credits_balance + is_super_admin）、credit_holds、credit_transactions、invite_codes 扩展（granted_credits）。
- 详见 Q4 的 SQL。

### AD5 ✅ deepseek stream_usage = 开启（Q5 确认）
- **代码验证**：`DeepSeekThinkingChatModel`（`deepseek_thinking.py:39`）继承 `ChatOpenAI`，未覆盖 stream_usage。
- 修改点：`models.py:64` 的 `stream_usage=provider != DEEPSEEK_PROVIDER` → `stream_usage=True`。
- 原理：`ChatOpenAI` 的 stream_usage=True 会传 `stream_options: {"include_usage": true}`，deepseek 兼容 OpenAI 协议会返回 usage。
- 适配器只覆盖了 `_get_request_payload`（reasoning 注水）和 `_convert_chunk_to_generation_chunk`（reasoning 提取），不影响 usage 传递链路。
- 风险：需实测确认 deepseek API 真的支持 stream usage（OpenAI 兼容但非 100%）。

### AD6 ✅ 预扣触发 = CreditsMiddleware 检测阶段转换（Q6 确认，已验证可行）

**可行性验证（代码确认 2026-07-09）**：
- 子代理委托通过 `task` 工具调用实现，CreditsMiddleware 的 `wrap_tool_call` 可拦截。
- `request.tool_call` 含 `name`（task）和 `args`（含 `subagent_type`）。
- interview 是第一个被委托的子代理（产出 demand.md，status: confirmed）。
- storybuilding 是 interview 之后的第一个"正式创作"子代理。

**预扣触发逻辑**：
```
CreditsMiddleware.awrap_tool_call(request, handler):
  if request.tool_call.name == "task":
    subagent_type = request.tool_call.args.get("subagent_type")
    if subagent_type == "storybuilding" and not self._hold_created:
      # 访谈结束，即将进入正式创作 → 预扣
      demand_md = read(workspace_path / "demand.md")
      tier = parse_tier_from_demand(demand_md)  # 解析篇幅档位
      hold = credits_service.create_hold(user_id, thread_id, trace_id, tier)
      if hold is None:  # 余额不足
        raise CreditExhaustedError("余额不足，无法开始创作")
      self._hold_created = True
  response = await handler(request)  # 放行执行
  return response
```

**中间件接口**（复用 TraceMiddleware 的 AgentMiddleware 模式）：
```python
class CreditsMiddleware(AgentMiddleware):
    def __init__(self, credits_service, trace_id, owner_id, workspace_path, agent_name):
        ...
    async def awrap_model_call(self, request, handler):
        response = await handler(request)
        usage = _usage_payload(response)  # 复用 trace_middleware 的提取逻辑
        if usage and self._hold_created:
            self._accumulate_usage(usage)     # 累加消耗
            self._check_credit_limit()         # 检查 -5000 强停线
        return response
    async def awrap_tool_call(self, request, handler):
        # 预扣检测（见上方逻辑）
        ...
```

**关键设计点**：
- `wrap_model_call`：每次 LLM 调用后提取 usage → 折算标准 token（D7）→ 累加到 hold.consumed → 检查余额是否触及 -5000（D27）→ 触及则抛 CreditExhaustedError。
- `wrap_tool_call`：检测 storybuilding 首次委托 → 触发预扣（D13）。
- CreditsMiddleware 只挂在 **meta agent** 和 **创作类子代理**（storybuilding/detail-outline/writing）上，不挂 interview（interview 不花创作积分——访谈本身是免费的）。
- A/B 测试/管理员路径：ctx.credits_recorder=None，CreditsMiddleware 不挂载（与 Trace 同模式）。

### AD7 ✅ 进化端管理后台架构 = evolution 后端代理转发（Q7 确认）
- 进化端前端（Next.js）→ evolution FastAPI 后端（新建 `/api/admin/*` 代理路由）→ 带 SSO cookie 转发到 executor `/api/admin/*`。
- 符合现有架构（所有 API 都走 evolution 后端）。
- evolution 后端代理路由负责：透传请求 + 传递 SSO cookie + 统一错误处理。

### AD8 ✅ 管理员 API 权限 = 全部要求 is_super_admin（Q8 确认）
- executor 所有 `/api/admin/*` 接口统一要求 `is_super_admin=1`。
- 现有 `is_admin=1` 校验改为 `is_super_admin=1`。
- 简单优先，当前只有超级管理员一人。将来需要分级再拆。

### AD9 ✅ 平台 key 配置 = 新建专门配置项（Q9 确认）
- 新增 settings 配置项 `PLATFORM_API_KEY` + `PLATFORM_BASE_URL`（与现有 `OPENAI_API_KEY` 区分）。
- `build_writer_model` 不再读用户的 `encrypted_api_key`，统一用平台 key。
- `_resolve_model` 不再传用户 key（D22 一刀切全转）。
- 现有 `OPENAI_API_KEY` 保留用于其他用途（如管理员兜底/测试）。

### AD10 ✅ 注册积分到账 = 注册即到账（Q10 确认）
- 邀请码的 `granted_credits` 在注册成功时直接加到 `users.credits_balance`。
- 记一条 `invite_grant` 类型流水（credit_transactions）。

### AD11 ✅ 积分配置 = 数据库 config 表 + 进化端管理页可改（Q11 确认）
- 新建 `credit_config` 表存暗调参数：三档权重、6 档预扣额度、负债上限、token→积分单价。
- 进化端管理页有"积分设置"页面，在线改，不重启。
- 需做缓存（启动时加载到内存，修改时刷新缓存）。

### AD12 ✅ 冻结拦截 = API 层 + 中间件层双保险（Q12 确认）
- API 层：创作相关 endpoint 加 `check_credits_frozen` 依赖，余额≤0 返回 403 友好提示。
- 中间件层：CreditsMiddleware 兜底，冻结用户 model_call 直接拦截（防绕过）。
