# 进化端 Agent 执行显示优化

## 核心诉求

把评估/进化页的 Agent 执行显示，从"内存里的平铺日志行"升级为"基于持久化 trace 的、
能看到思考过程和执行层次的、切走再回来能完整恢复的"步骤流式可视化。

## 现状诊断（已勘察确认，作为本次改造的事实基线）

| 显示形态 | 位置 | 内容 | 持久化 |
|---|---|---|---|
| 平铺日志行 | 评估页 / 进化页（`liveLogs` useState） | SSE 帧 type/message/tool | ❌ 切走即丢 |
| 节点树 + 思考过程抽屉 | `/traces/:traceId` 详情页 | 完整调用链 + LLM input/output | ✅ 从 DB 重新加载 |

关键事实（基于代码勘察）：
- 后端 trace recorder 已全程记录业务事件 + 框架事件（`append_business_event` + middleware 的 llm/tool 事件）。
- 评估/进化页**没接 trace 可视化**，自起炉灶搞了平铺日志流。
- 后端 SSE 端点**只推订阅后新帧**，订阅前历史不回放。
- SSE 派生函数 `_trace_event_to_sse` 显式丢弃 LLM/tool 框架事件（注释："暂不推，避免刷屏"）。
- session_id → trace_id 映射**只在内存字典** `_session_trace`，进程重启即丢，SSE 端点 404。
- 隐式通道：`runs.thread_id = session_id`（create_run 时写入），可反查。
- agent emit 的 step 帧 `tool` 字段是**函数名**（如 `read_trace`/`edit_source`），**不是人话**。
- 进化页详情卡片字段几乎全是废弃字段（phase 恒 "—"、baseline/candidate_score 恒 null、baseline/candidate_trace 按钮永不出现）。

## 功能需求

### F1. session → 自观测 trace_id 持久化通道（后端）

**目的**：消除"进程重启即丢映射"的脆弱点，让进入页面重放历史能走通。

**需求**：
- 在 `eval_agent/api.py` 的 `get_session` / `list_sessions` 端点、`evolve/api.py` 的 `get_session` / `list_sessions` 端点中，对每个 session 反查：
  `SELECT trace_id FROM runs WHERE thread_id = ? AND run_purpose IN ('evolution_eval', 'evolution_evolve') ORDER BY started_at DESC LIMIT 1`
  内联为 `trace_id_self` 字段返回。
- `core/db.py` 给 `runs.thread_id` 加索引（`idx_runs_thread`），避免全表扫。
- 前端 `EvalSession` / `EvolveSession` 类型增加 `trace_id_self?: string` 字段。

**不做**：
- 不修改业务表 schema（`evaluation_sessions` / `evolve_sessions` 不加 trace_id_self 列）。`runs.thread_id` 这条隐式通道已经够用，新增列属于冗余。
- 不废弃 `_session_trace` 内存字典（仍作为热路径缓存，反查未命中时再用内存兜底，避免冷热两套来源割裂）。

**异常**：
- 反查无结果（session 没启动过 trace 或 trace 已清理）→ `trace_id_self` 返回 null，前端不显示执行流视图。

---

### F2. 执行流视图（前端，步骤流式可折叠）

**目的**：替换现有平铺日志流，提供美观、聚焦关键信息的执行过程可视化。

**视觉形态**：
- 纵向步骤列表，每个 step 一个区块。
- 每个区块默认折叠，显示：状态图标 + 步骤标题（人话）+ 状态文字 + 耗时（已完成的步骤）+ 来源标签（log / step / llm / tool）。
- 进行中的步骤高亮（如左侧色条 + 动画），自动滚动到视口。
- 点击步骤展开：显示该步骤的思考摘要（如 agent message）+ 「查看 LLM 原文 →」（懒加载）。
- 失败步骤：红色高亮 + 错误信息直接显示（不用展开）。

**步骤标题来源**（D7 前端字典翻译）：
- 前端维护 tool → 中文 label 映射，如：
  - `read_trace` → "读取 trace 摘要"（+ trace_id 前 8 位）
  - `edit_source` → "修改源码"（+ 文件相对路径）
  - `write_design_doc` → "撰写方案文档"
  - `write_change_log` → "记录改动清单"
  - `write_eval_report` → "撰写评估报告"
  - `get_content_score` → "内容打分"
  - `validate_changes` → "校验改动"
- 未命中字典的 tool：显示原函数名 + "（未翻译）"标记。
- `emit_log` 类型的帧（agent 主动的人话）：直接显示 message，不套字典。

**状态语义**：
- `running` → 进行中（动效）
- `done` / `completed` → 已完成（打勾）
- `failed` → 失败（红 ×）
- `cancelled` / `stopped` → 已停止（停止符）
- 未到达的步骤：不渲染（基于已知步骤列表预渲染？还是仅按已到达事件渲染？——见 F5）

**位置**：
- 评估页 / 进化页右侧详情区，用 **Tab 切换**：「执行流」|「报告」。
- 运行中默认激活「执行流」tab；流终态后自动切到「报告」tab，但允许用户切回「执行流」回看。
- 原平铺日志流**完全替换**（不留双视图，避免信息重复）。

**顶部工具栏**：
- 当前 session 状态徽章（运行中/已完成/失败/已停止）。
- 总耗时 / 步骤数 / 错误数 摘要条。
- 「停止」按钮（运行中可见，复用现有 `stopEval` / `stopEvolve` 接口，位置从原徽章挪到这里）。
- 「查看完整 trace 节点树 →」跳转入口（保留独立 trace 详情页作为深潜工具）。

### F3. 历史回放 + SSE 增量（前端）

**目的**：解决"切走就丢"的核心痛点。

**需求**：
- 进入页面（组件挂载）时：
  1. 从 session 拿 `trace_id_self`。
  2. 若 `trace_id_self` 存在：调 `getTraceDetail(trace_id_self)` 拉当前节点投影（已完成的 step）。
  3. 调 `getActiveRuns()` 判断 trace 是否仍在运行。
  4. 若仍在运行：开 `evoSseStream('/api/.../sessions/{id}/stream')` 接 SSE 增量。
- 历史已完成的 step 直接渲染（不动画重放——动画重放价值低于即时可见，且耗时）。
- SSE 新到达的 step：增量追加到列表，自动滚动到视口。
- 同一 step 的多次状态更新（如 `running` → `done`）：原地更新状态图标，不重复插入。

**不做**：
- 不做"按时间间隔动画重放历史"——已完成的步骤直接显示最终状态即可。重放动画成本高、价值低。

**异常**：
- session 运行中但 `trace_id_self` 反查无结果（极端场景：trace 创建晚于 session 行）→ 显示"等待 trace 启动…"，retry 几次后降级为只显示运行中徽章。
- SSE 断连 → 显示"连接断开，正在重连…"，自动重连（指数退避，最多 5 次）。
- session 已终态 → 不开 SSE，只显示历史快照。

---

### F4. 解锁 LLM 框架事件 SSE 推送（后端）

**目的**：让执行流能展示 LLM 思考步骤（目前被 SSE 派生函数显式丢弃）。

**需求**：
- 修改 `eval_agent/api.py:306-322` 和 `evolve/api.py:371-379` 的 `_trace_event_to_sse`：
  - 对 `llm_start` / `llm_end` / `tool_start` / `tool_end` 框架事件，派生成新的 SSE 帧类型（如 `llm_step` / `tool_step`）。
  - 帧内容只含骨架信息：`type` / `event_type` / `agent_name` / `depth` / `node_name` / `status` / `duration_ms`。
  - **不带** input/output 全量原文（避免 SSE 刷屏 + 流量爆炸，详情走 F5 懒加载）。

**节流**：
- 同一 `run_id` 的连续事件按 100ms 节流（防高频 tool 调用刷屏）。
- 超时未刷新的 `*_start` 事件：UI 显示进行中（用最后已知状态）。

**不做**：
- 不在 SSE 推 LLM input/output 原文。详情走懒加载。
- 不重写 SSE 协议（继续用 `data:` 帧，新增 `type` 值）。

### F5. 思考原文懒加载（前端）

**目的**：用户点击展开某 step 时，拉取该步骤的完整 LLM input/output。

**需求**：
- 复用已有接口（无需后端新增）：
  - `getTraceEvents(traceId, eventIds)` 按 event_id 批量拉原始事件。
  - `getTraceContext(traceId, anchorId)` 按 anchor_id 拉 context segment。
- 展开抽屉内容（与 trace 详情页抽屉机制一致）：
  - LLM 节点：显示 messages 列表（system / human / ai / tool 消息分别样式），长内容（>10 行）折叠 + 展开按钮。
  - Tool 节点：显示 tool_args + tool_output。
  - 失败节点：显示错误堆栈。

**不做**：
- 不预加载所有节点的详情（流量大），仅按需。
- 不重写抽屉组件——可直接复用 `TraceChainDrawer.tsx` 内部子组件（`ModelInputMessage` / `DrawerLLMContent` / `DrawerToolContent`），但**外层容器**是执行流视图的一部分，不是独立抽屉。

## 边缘场景

### E1. session 运行中切走再回来
- 组件挂载 → 拉 `trace_id_self` → 拉历史投影 → 接 SSE。
- 已完成的 step 直接显示，新到的增量追加。

### E2. session 已终态（completed / failed / cancelled）
- 不开 SSE，只显示历史快照。
- 「报告」tab 自动激活。

### E3. 进程重启后访问历史 session
- `_session_trace` 内存空，但 `runs.thread_id` 反查能拿到 trace_id_self。
- 历史投影正常加载（trace 数据持久化在 DB + WAL）。
- SSE 不开（session 已终态）。

### E4. session 启动但 trace 还没创建
- `trace_id_self` 反查无结果。
- 显示"等待 Agent 启动…"，retry 3 次后降级为只显示状态徽章。

### E5. SSE 断连
- 显示"连接断开，正在重连…"，指数退避重连（最多 5 次）。
- 重连期间已显示的步骤不丢失（仍在内存 + 后续可从 trace 投影恢复）。

### E6. step 状态反转（done → failed）
- 后端理论上不会发生（终态不可逆）。若收到，以最后到达的状态为准。

### E7. 高频 tool 调用刷屏
- 后端按 100ms 节流同 `run_id` 事件（F4）。
- 前端列表虚拟化（步骤 > 50 条时启用，避免 DOM 性能问题）。

- 后端 trace_id_self 反查命中/未命中打日志（便于排查映射丢失）。
