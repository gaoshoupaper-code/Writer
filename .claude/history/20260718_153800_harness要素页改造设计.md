# Harness 要素页改造 · 设计文档

## 设计目标

把"Agent 要素"页改造成"Harness 要素"页——三件套落地：
1. **改名 Harness**：前端文案 + TS 类型 + 后端 API 路径同步重命名
2. **新增 Tools Tab**：按文件展示，docstring 首句为描述，跨版本去重
3. **Memory 降级为统一 Tab**：保留 4 阶段流水线叙事，Tab 化对齐其他要素

## 全局扫描结论（已读代码）

### 当前数据流
```
HarnessPage (harness.tsx)
  ├─ getSnapshots() → GET /api/snapshots
  ├─ getElements(v) → GET /api/snapshots/{v}/elements
  │     → ElementsView { agents: AgentElementView[], ... }
  │     → 每个 agent 含 prompt/skills/middlewares（无 tools 字段）
  ├─ getMemoryElements(v) → GET /api/snapshots/{v}/memory-elements
  │     → MemoryElementsView { elements: MemoryElementView[] }
  │     → 独立卡片，按 extract→store→retrieve→recall 排序
  └─ getVersionDetail(v) → GET /api/versions/{v}
        → changes.agents[].diff（含 prompt/skills/processors diff）
```

### 后端扫描模式（已存在，可复用）
- `_list_files_at_commit(commit, subdir)` → 列某 commit 下某目录所有文件
- `_build_skill_infos(commit)` → 扫 `skills/`，读 SKILL.md frontmatter
- `_build_middleware_infos(commit)` → 扫 `middleware/`，`ast.get_docstring()` 提取
- **缺**：`_build_tool_infos(commit)` —— 仿照 middleware 的模式新增

## 第一轮决策（架构骨架）

### 决策 A1：Tools 数据结构——**顶层平级**，不挂 agent

`HarnessElementView` 顶层新增 `tools: ToolInfo[]`，与 `agents[]` 平级。

**依据（经代码查证）**：harness 的 `tools/` 目录是全局平铺的，不存在"tool → agent"映射。5 个 .py 文件作用域各异（全局/middleware 注入/meta 专属/writing 专属/记忆系统），无法按 agent 分组。

**对需求文档的修正**：
- 需求 D6 原文"按文件（对齐 Skills）"——**部分作废**。Skills 是按 agent 分段，Tools 是平铺一列。两者格式无法对齐。
- Tools Tab 的展示形态改为：**平铺列表**，每行一个 tool 文件 + 描述 + **作用域标注**。

### 决策 A2：ToolInfo 数据结构

```ts
interface ToolInfo {
  path: string;              // 如 "tools/goal.py"
  name: string;              // 文件名去后缀，如 "goal"
  description: string | null;// 模块 docstring 首句
  scope: ToolScope;          // 真实作用域（见下）
  load_error: string | null; // 解析失败时填
}

// 作用域标注——诚实反映 harness 里 tool 的真实归属
type ToolScope =
  | { kind: "global" }                              // 全局注入（如 join_rules 进 MemoryRetriever 单例）
  | { kind: "middleware"; via: string }             // 经 middleware 暴露（如 goal 经 GoalMiddleware）
  | { kind: "agent"; agent: string }                // 仅某 agent 专属（如 query_builder 仅 writing）
  | { kind: "memory" };                             // 记忆系统策略（如 narrative_schema）
```

### 决策 A3：Memory 数据流——**保持独立接口**

Memory 仍用 `/harness-elements/memory` 独立接口、独立拉取。HarnessPage 里只是把 `MemorySubsystemCard` 从页顶移到 Tab body。最小改动，保留数据独立性。

### 决策 A4：~~Tools diff——复用 skills 机制~~ **作废（见下方"diff 死管道"风险）**

> ⚠️ **查证后推翻**：整个 diff 管道（Prompt/Skills/Middleware/Tools）当前是**死的**。
> - 后端 `GET /api/versions/{v}` 不返回 `changes` 字段
> - `version_changes` 表已被 DROP（`db.py:178`），写入层 `config_diff.py`/`version_changes_repo.py` 已删
> - 前端 `versionDetail.changes` 永远是 undefined，所有 diff 高亮静默失效
> - 项目自己承认（`versions.tsx:14` 注释）："version_changes 写入层尚未实现，完整 diff 待后续修复"
>
> **本次需求不碰 diff**——重建 version_changes 写入链是大工程，超出"Agent要素改造"范围。
> 本次只做：改名 + Tools Tab 展示 + Memory Tab 化。所有 diff 高亮（含 Tools）本次都不做。

## 第二轮决策（数据来源与边界）

### 决策 B1：ToolInfo.scope 来源——**后端硬编码映射表**

在 `evolution/app/versioning/constants.py` 新增 `TOOL_SCOPE_MAP`：

```python
TOOL_SCOPE_MAP: dict[str, dict[str, str]] = {
    "tools/goal.py":              {"kind": "middleware", "via": "GoalMiddleware"},
    "tools/query_builder.py":     {"kind": "agent", "agent": "writing"},
    "tools/join_rules.py":        {"kind": "global"},
    "tools/packet_formatter.py":  {"kind": "global"},
    "tools/narrative_schema.py":  {"kind": "memory"},
}
```

**依据**：harness 的 tool 总数就 5 个且变动极少（harness 进化以 prompt/middleware 为主），硬编码可审查、零解析成本。新增 tool 时同步更新此表（约定）。

**前端兜底**：后端扫到 tools/ 下有文件但 `TOOL_SCOPE_MAP` 里查不到 → `scope = { kind: "unknown" }`，前端显示"⚠ 未登记作用域"，提醒开发者补登记。避免新 tool 静默漏标。

### 决策 B2：Tools Tab 全展——**废除 D5 过滤**

Tools Tab 展示 `tools/` 下**全部**文件（含记忆类），每个用 scope 诚实标注归属。
与 Memory Tab（流水线视角）互补——同一批文件，两个视角：
- **Tools Tab**：按文件平铺，看"harness 里有哪些可进化 tool 文件 + 各自给谁用"
- **Memory Tab**：按流水线阶段聚合，看"记忆系统怎么运转"

**对 ToolScope 类型的补充**：加 `"unknown"` 兜底 kind。
```ts
type ToolScope =
  | { kind: "global" }
  | { kind: "middleware"; via: string }
  | { kind: "agent"; agent: string }
  | { kind: "memory" }
  | { kind: "unknown" };  // 兜底：TOOL_SCOPE_MAP 未登记
```

### 决策 B3：Memory Tab 空态——**始终显示 Tab + 空态提示**

Memory Tab 始终存在于 TabsList（5 个 Tab 数量固定）。
早期版本（无 NWM 重构）memory elements 为空时，Tab body 显示"此版本无记忆子系统（早于 NWM 重构）"，沿用 `MemorySubsystemCard` 既有空态文案。
Tab 数量不随版本跳变，交互稳定。

## 第三轮决策（UI 与辐射面）

### 决策 C1：Tools Tab 布局——**平铺 + scope 彩签**

一列平铺所有 tool 文件，每行右侧挂彩色 scope 标签（仿 AgentBadge 风格）。
- `global` → 灰色"全局"
- `middleware` → 蓝色"经 GoalMiddleware"
- `agent` → 紫色"writing 专属"
- `memory` → 橙色"记忆系统"
- `unknown` → 红色"⚠ 未登记"

### 决策 C2：~~Tools diff——只 added/removed~~ **作废（diff 死管道，见决策 A4）**

本次不做任何 diff 高亮。Tools Tab 只做静态展示（path + description + scope 彩签）。

### 决策 C3：改名辐射——**只改可见文案**

- ✅ 改：h1、导航 label、toast 文案、代码注释、TS 类型名、后端 API 路径
- ❌ 不改：URL `/harness`、文件名 `harness.tsx`、组件名 `HarnessPage`（已是 Harness 语义，URL 改破坏书签）

### `GET /api/snapshots/{v}/harness-elements` 响应结构

```ts
interface HarnessElementsView {        // 原 ElementsView 改名
```

## 已知问题（独立于本次需求，记录防踩坑）

### 🔴 diff 管道整体失效（既有 bug，本次不修）

**现象**：harness 页的 Prompt/Skills/Middleware diff 高亮功能当前完全失效，用户永远看到"本版本无要素变更记录"。

**根因**：
- 后端 `GET /api/versions/{v}`（`versions_api.py:76`）不返回 `changes` 字段
- `version_changes` 表已被 DROP（`db.py:178`），写入层 `config_diff.py`/`version_changes_repo.py` 已删
- 前端 `versionDetail.changes` 永远是 undefined，静默降级

**残留死代码**（后续清理或重建时处理）：
- `evolution/scripts/backfill_version_changes.py` — import 已删模块，跑不起来
- `evolution/app/versioning/__init__.py` — 导出列表含已删的 `config_diff/snapshot_repo/version_changes_repo`
- `evolution/app/evolve/docs.py:149` — 死注释提 version_changes

**修复路径**（未来独立需求）：重建 version_changes 写入链 → 后端注入 changes → 前端 diff 恢复 → 再加 Tools diff。这是大工程，不应混入"Agent要素改造"。

**对本次需求的影响**：Tools Tab 只做静态展示，不做 diff 高亮。Memory 流水线也不做节点替换标记（原需求 D3/D7 的 diff 部分全部推迟到 diff 管道修复后）。
