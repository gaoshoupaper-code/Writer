# 第一期设计：进化端记忆要素对齐

## 范围（对应需求 D11 第一期）

1. 桌面静态要素可识别（D10-1）：6 个记忆要素在 harness 页能被徽章识别 + 筛选。
2. 进化 Agent 能认知记忆要素（D10-3）：prompt 加"记忆子系统"节。

## 调研发现的关键断层（必须在 R1 解决）

### 后端 elements API 不返回 5/6 的记忆要素

后端 `evolution/app/versioning/elements_api.py` 的 `build_elements_view`（:147）只扫三处：
- `skills/` → `_build_skill_infos`（:95）
- `middleware/` → `_build_middleware_infos`（:122，含 source_path）
- `prompts/meta_system.md` + `prompts/{sub_name}_system.md`（:171,:184，只读 system prompt，单 body 字符串）

**6 个记忆要素的暴露情况**：
| 要素 | API 是否返回 | 识别字段 |
|---|---|---|
| `middleware/memory_recall_middleware.py` | ✅ 返回 | `source_path` |
| `tools/narrative_schema.py` | ❌ tools/ 未扫描 | — |
| `tools/query_builder.py` | ❌ tools/ 未扫描 | — |
| `tools/join_rules.py` | ❌ tools/ 未扫描 | — |
| `tools/packet_formatter.py` | ❌ tools/ 未扫描 | — |
| `prompts/memory_extraction_guide.md` | ❌ 只读 *_system.md | — |

**后果**：需求 D10-1 要求"6 个记忆要素都能被徽章识别"，但当前后端下 5 个根本不进前端。
不解决这个，第一期桌面验收直接失败。

## 进化 Agent prompt 改动方向（已调研清楚，低风险）

- `evolve_system_prompt`（`prompt.py:18-226`）是 f-string 一次拼好，但已有 `reflections_section` 条件注入先例（:32-40）。
- 调用点唯一：`agent.py:70-75`，可仿 `_format_reflections`（:246-292）做 `_format_memory_section`，检测 `settings.harness_work_dir_path` 下有无记忆要素文件，有则注入表格，无则空串。
- 插入位置：③ 段"Agent 要素全景"内、"### 审稿审查器"小节（:99）之前，作为"### 记忆子系统（NWM 可进化要素）"子节。
- 表格用 4 列 `| 要素 | 目录 | 是什么 | 起什么作用 |`，与 ③ 段包内要素表（:84）对齐。
- 这块改动面小、无外部依赖，不是设计难点。难点在桌面那块（依赖后端 API 扩展）。

## 已确认决策（R1）

### S1. 后端 = 独立 memory-elements 接口
新开 `GET /api/snapshots/{version}/memory-elements`，专门返回当前 harness 版本的 6 个
记忆要素。后端逻辑独立，不污染现有 elements（按 agent 分组）语义。
- 记忆要素横跨 tools/middleware/prompts 三目录、不属于任何 agent，独立接口语义最干净。
- 前端拿到后展示在顶部集中卡片（见 S3）。

### S2. 识别标记 = 后端打 tag 字段
后端扫描时按集中维护的 `MEMORY_FILES` 清单给命中文件打 `tags: ["memory"]`
（或 `is_memory: true`）。前端只读字段，不硬编码文件名。
- 6 文件名无共同前缀，前端硬编码脆；后端集中清单改名只改一处。

### S3. 桌面展示 = 顶部"记忆子系统"集中卡片（修订需求 D2/D7）
harness 页顶部加"记忆子系统"卡片，集中展示 6 要素（名称/路径/作用）+
抽取→存储→检索→回填协同关系。**不散落各 Tab**。
- 已同步修订需求 D2（融入分组→集中卡片）、D7（徽章筛选→集中卡片）、D10-1（验收口径）。
- 各 Tab 原有 middleware 等展示不变（顶部卡片是额外聚焦视图，不取代）。

## 已确认决策（R2）

### S4. 接口 schema = 扁平 list + role 字段
```jsonc
// GET /api/snapshots/{version}/memory-elements
{
  "version": 3,
  "has_source": true,
  "elements": [
    {
      "name": "memory_extraction_guide",
      "path": "prompts/memory_extraction_guide.md",
      "type": "prompt",           // prompt | middleware | tool
      "file_role": "extract",      // extract | store | retrieve | recall
      "description": "记忆抽取器 system prompt 覆写源",
      "tags": ["memory"]
    },
    // ... 其余 5 个
  ]
}
```
- 扁平 list 每条带 `file_role`（extract/store/retrieve/recall），前端按 role 分组渲染流水线。
- 扩展性：新要素加新 role，不改结构。
- type 字段让前端知道这是 prompt/middleware/tool（虽集中展示，但保留类型信息备用）。

### S5. 卡片布局 = 横向流水线
顶部"记忆子系统"卡片内部：抽取 → 存储 → 检索 → 回填 四阶段从左到右，
每阶段下方挂属于该 file_role 的要素：
- 抽取(extract)：memory_extraction_guide
- 存储(store)：narrative_schema
- 检索(retrieve)：query_builder, join_rules, packet_formatter（3 个竖排或子流水线）
- 回填(recall)：memory_recall_middleware
直观体现 NWM 数据流。

### S6. MEMORY_FILES 清单 = elements_api 模块常量
在 `evolution/app/versioning/elements_api.py` 顶部加模块级常量：
```python
MEMORY_FILES = {
    "prompts/memory_extraction_guide.md": ("prompt", "extract", "记忆抽取器 system prompt 覆写源"),
    "tools/narrative_schema.py": ("tool", "store", "..."),
    "tools/query_builder.py": ("tool", "retrieve", "..."),
    "tools/join_rules.py": ("tool", "retrieve", "..."),
    "tools/packet_formatter.py": ("tool", "retrieve", "..."),
    "middleware/memory_recall_middleware.py": ("middleware", "recall", "..."),
}
```
路径 → (type, file_role, description)。被扫描打 tag + 接口返回 + Agent 探测三处复用。

## 已确认决策（R3）

### S7. 进化 prompt 记忆节 = 表格 + 协同说明
4 列要素表（与 ③ 段包内要素表对齐）+ 一段简短协同说明
（抽取→存储→检索→回填一句话串联）。不加 ASCII 流水线图（桌面已画，prompt 不重复）。

### S8. 软约束 = 总注不逐个
要素表后加一句总注："这 6 个是 NWM 记忆子系统，改 query_builder/join_rules/
packet_formatter 会影响检索一致性，慎改。"不逐个要素写风险列（避免表格变宽、prompt 变长）。

### S9. 接口 diff = 复用前端 diff 模式（遵循现有架构一致性）
**一致性决策**（非用户拍板，遵循现有 elements 架构）：现有 `GET /elements` 只返回单版本，
diff 由前端拿两版本数据自己算（各 Tab 有"显示升级差异"toggle）。
memory-elements 照抄此模式——接口只返回单版本 elements，diff 复用前端现有 diff 模式。
- 后端零额外 diff 逻辑，前端 diff 逻辑可复用。
- ~~后端做 diff（?compare_to=X）~~ 不采纳，与现有架构不一致。

## 已确认决策（R4）

### S10. MEMORY_FILES 位置 = evolution/app/versioning/constants.py（新文件）
**归类决策**（基于现有架构，非用户拍板）：
- `contracts/` 是 executor/evolution 跨端契约，MEMORY_FILES 是 evolution 内部两模块共享，
  放 contracts 语义偏高。
- 记忆要素认定本质是"harness 包版本的要素分类"，属 versioning 域常量。
- 放 `evolution/app/versioning/constants.py`，elements_api 和 evolve/agent 都 import，
  依赖方向自然（evolve → versioning 合理，反向不行）。

```python
# evolution/app/versioning/constants.py
"""Harness 包要素分类常量（versioning 域共享）。

被 elements_api（扫描打 tag + 接口返回）和 evolve/agent（prompt 注入探测）复用，
确保前后端认定"什么是记忆要素"同源。
"""

# 记忆子系统要素清单：path → (type, file_role, description)
# type: prompt | middleware | tool
# file_role: extract | store | retrieve | recall
MEMORY_FILES: dict[str, tuple[str, str, str]] = {
    "prompts/memory_extraction_guide.md": ("prompt", "extract",
        "记忆抽取器 system prompt 覆写源，引导 LLM 抽取 typed records"),
    "tools/narrative_schema.py": ("tool", "store",
        "NWM 记忆可进化 schema 策略，决定抽哪些类型记录、按题材启用/禁用 record 类型"),
    "tools/query_builder.py": ("tool", "retrieve",
        "查询构造器，task description → writer query"),
    "tools/join_rules.py": ("tool", "retrieve",
        "One-Hop JOIN 规则，anchor 节点扩展一跳邻域"),
    "tools/packet_formatter.py": ("tool", "retrieve",
        "证据包排版器，检索结果 → 注入文本"),
    "middleware/memory_recall_middleware.py": ("middleware", "recall",
        "MemoryRecallMiddleware，写作前召回中间件"),
}

# file_role 的展示顺序（抽取→存储→检索→回填）
MEMORY_ROLE_ORDER = ["extract", "store", "retrieve", "recall"]
```
