# 桌面端更新机制重设计

## 核心诉求

进化端和创作端桌面应用，用户能**明确感知到有新版本**，并能看到**新版本更新了什么内容**，由用户手动决定是否更新。提示方式轻量，不打扰用户。

## 背景与根因（已确认）

### 之前的"看不到更新"根因 ≠ updater 机制有问题

经彻查确认：**当前 Tauri updater 机制（版本号比较 + 签名验证）本身工作正常**。
真正的根因是：**用户机器上装的是更新功能代码加入之前的旧版本**（commit `9d25484` 之前构建的包），那个版本里压根没有 updater 代码（无 UpdateBanner、无检查更新按钮），所以永远不会检查更新。

> 这是所有自动更新机制的固有死锁：**第一个带 updater 的版本必须手动安装**，没有例外。

### updater 链路已验证正常的部分（本次不改）
- `tauri.conf.json` 的 updater 配置（endpoints、pubkey）两端正确 ✅
- `capabilities/default.json` 的 `updater:default` 权限 ✅
- `updater.rs` 的 check_update / install_update / check_on_startup 逻辑 ✅
- 启动时自动检查 + emit event ✅
- 签名机制（已修复脚本选错产物 + 自检关卡）✅

## 需求规格

### 功能 1：启动时自动检查更新
- **触发时机**：App 启动时自动检查一次（沿用当前 `check_on_startup`）。
- **有新版**：窗口顶部出现更新提示条。
- **无新版 / 检查失败**：不打扰用户，静默处理（沿用当前行为）。
- **范围**：进化端 + 创作端均需支持。

### 功能 2：更新提示条 + 展示更新内容
- **提示形式**：窗口顶部横条（沿用当前 UpdateBanner 的位置和样式）。
- **横条内容**：「✨ 发现新版本 vX.X.X」+「立即更新」按钮 + 「更新内容」可展开。
- **更新内容展示方式**：**点击后展开**，显示本次版本的更新条目列表（changelog），用户看完再决定是否点「立即更新」。
- **手动触发**：保留现有「配置页/设置页」的「检查更新」按钮（点击后提示结果，有新版则顶部横条同步出现）。

### 功能 3：更新内容（changelog）来源与格式
- **来源**：自动读取 git log。
- **范围**：只取**本版本相对上个版本新增的 commit**（不重复展示旧版本的）。
- **格式处理（轻量过滤）**：
  - 去掉 conventional commit 的 type 前缀（`feat:`、`fix:`、`chore:`、`refactor:` 等）
  - 去掉 scope 括号（`(updater)`、`(desktop)` 等）
  - 去掉 merge commit（`Merge branch...`）
  - 去重复
  - 保留中文原文（commit message 本身就是中文，用户可读）
- **写入位置**：latest.json / latest-evo.json 的 `notes` 字段（当前只写了「思衍 v0.2.2」一句话，改为多行 changelog）。

### 功能 4：更新动作
- **策略**：只提示，用户手动触发下载安装（沿用当前策略，不自动下载）。
- 用户点「立即更新」→ 下载 + 验签 + 安装 + 重启（沿用 install_update）。

## 约束

### 技术约束
- 不抛弃 Tauri updater，换正确的方式使用它（当前用法已正确，只需补充 changelog 展示）。
- 签名验证机制保留（安全要求）。
- 两端（进化端/创作端）的更新 UI 和后端逻辑保持对称（沿用当前"照搬"模式）。

### 流程约束（发布脚本需配合）
- **必须建立 git tag 机制**：当前只有 `v0.1.0` 一个 tag，且与桌面端版本号体系不一致。为支持"只取本版本新增 commit"，发布脚本需在发版时打 tag（如 `evo-v0.2.2` / `creator-v0.1.2`），下次发版时 `git log <上个tag>..HEAD` 取增量 commit。
- **首次发布无上个 tag 时**：回退为取最近 N 条（如 10 条）commit，并标注。

### ⚠️ 关键约束：发版必须联动更新官网下载页（当前断链，是核心痛点）

**现状（致命断链，已确认）**：
- 官网下载页 `download.astro` 版本号**硬编码** `VERSION = "0.1.1"`，发版脚本 `publish.sh` 完全不更新它。
- 首页 `index.astro:89` 同样硬编码 `v0.1.1`。
- 下载页**只有创作端**，没有进化端下载入口。
- 后果：用户从官网下载的永远是 0.1.1（没有 updater 代码的旧版），所以**永远看不到更新提示**——这是"看不到更新"的真正根因之一。

**要求（必须解决）**：
- 发版脚本完成后，**自动更新官网下载页 + 首页的版本号**（让下载链接指向最新版），并重新部署官网。
- 下载页需补充**进化端**下载入口。
- 这样才能保证：用户随时从官网下载到的，都是带 updater 代码的最新版。

### 不做（明确排除）
- ❌ 不做下载进度条（用户未要求）。
- ❌ 不做强提醒/弹窗/红点徽章（用户只要"稍微提示"）。
- ❌ 不做定时检查（只要启动时检查一次）。
- ❌ 不做自动下载（只提示，手动触发）。
- ❌ 不重写 updater 核心机制（Rust 后端逻辑正确）。
