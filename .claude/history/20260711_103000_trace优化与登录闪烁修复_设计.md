# 架构方向（待确认）

分两阶段交付：先登录闪烁（影响面大、改动独立），后 trace 优化（架构重构重）。

## 设计断层（Step 0 识别，待逐个击破）

### 阶段一：登录闪烁
- **T1**：Rust cookie jar 持久化——reqwest 的 `cookie_store(true)` 是黑盒 jar，没有公开 API 提取 cookie。怎么把 cookie 持久化到 Tauri Store？
- **T2**：503 重试的具体参数（重试次数、退避间隔、最大时长）
- **T3**：Shell 守卫重试策略（重试几次？全部失败显示重试按钮 vs 跳登录？）

### 阶段二：Trace 优化
- **T4**（最关键）：projector 增量化的技术路线——真增量化（每个 event O(1) 增量）vs 全量+diff（每次 O(N) 全量投影再 diff）。决定整个阶段二的复杂度和正确性风险。
- **T5**：SSE 双数据源统一——evolution 自产 trace（recorder queue，推 node patch）与 executor 创作 trace（HTTP 中继，推原始 event）怎么共存？前端怎么区分？
- **T6**：node patch 的数据结构（append/update/delete 的信封格式）
- **T7**：projector 增量化降级策略（recorder 崩溃重启后投影状态丢失）
- **T8**：详情接口 events 懒加载的查询契约（按 node_id 还是 seq 范围）
- **T9**：终态一致性（运行期增量投影 vs 终态全量投影，两者结果可能不一致）

## 第一轮决策（2026-07-11）

- **T4 Projector 路线 = 路线 Y（全量+diff）**：projector 投影逻辑零改动（复用已验证逻辑），运行期每次全量投影后与前次快照 diff，只推 diff。后端每次 O(N) 但节流（~500ms）后扛得住上千事件；前端只收 patch，O(N²) 根除。
- **T1 Cookie 持久化 = cookie_store crate**：引入 `cookie_store` + `cookie` 依赖，用 `cookie_provider(Arc<jar>)` 注入可序列化 jar，jar 持久化到 Tauri Store（settings.json）。
- **T5 SSE 双源 = 统一信封按 source 分流**：SSE 消息加 `source` 字段（evolution/executor），evolution 源推 node patch（后端投影），executor 源保持推原始 event；前端按 source 分流处理。

## 第二轮决策（2026-07-11）

- **T6 Patch 粒度 = node 级全量替换**：diff 比对 node_id 集合 + 字段 hash，变更的 node 整个发给前端（按 node_id 覆盖）。node 本身是精简结构（KB 级），传输量可接受。
- **T2/T3 重试参数 = 标准容错**：503 重试最多 3 次指数退避（1s/2s/4s）；Shell 守卫 fetchMeOrNull 失败重试 2 次，全失败才跳登录；全局 401 去抖窗口 500ms（窗口内多次 401 只跳一次）。
- **T9 终态一致性 = 终态全量 snapshot**：trace 终态时后端发全量 snapshot（node 列表全量），强制前端对齐。复用 SSE 已有 `_type: snapshot` 机制。运行期用 diff 推增量，终态用 snapshot 纠正。

## 第三轮决策（2026-07-11）

- **T7 崩溃恢复降级 = 天然免疫**：路线 Y（全量+diff）每次从 DB 全量重算，recorder 崩溃重启后第一次投影就是全量，diff 结果即全量 append。无需额外降级逻辑（相比真增量化路线 X，这是路线 Y 的额外优势）。
- **T8 events 懒加载 = 按 event_ids 批量查**：前端打开抽屉时用 `node.raw_event_ids` 调 `GET /api/traces/{id}/events?event_ids=a,b,c` 拉回原始事件。TraceNode 已有 raw_event_ids 字段，无需加字段。
- **context 懒加载 = 也懒加载**：详情接口不返回 context 全量，改为 `GET /api/traces/{id}/context?anchor_id=xxx` 按 anchor 拉取。详情接口最终只返回 `run + nodes + todos`。

## 第四轮决策（2026-07-11）·最终轮
- 接口契约全貌：**确认无误**
- WBS 任务拆解粒度：**按推荐粒度**（每任务可独立验证）

# 一、架构快照

## 阶段一：登录闪烁修复（容错 + 持久化）

```
当前：任意 401 → 全局跳登录（无去抖）+ cookie jar 内存（重启丢失）
     ↓
目标：
  ① 后端 SSO 区分 503/401（executor 不可达 → 503，session 失效 → 401）
  ② 前端 503 静默重试（3次指数退避），401 去抖（500ms 窗口只跳一次）
  ③ Shell 守卫重试（fetchMeOrNull 失败重试 2 次才跳登录）
  ④ Rust cookie jar 持久化（cookie_store crate → Tauri Store）
```

**技术栈变更**：Rust 端引入 `cookie_store` + `cookie` crate，替换 `cookie_store(true)`。

## 阶段二：Trace 优化（投影后移 + 数据懒加载）

```
当前：后端详情接口全量返回 events（O(M×N) 增量重建）
     + 前端 SSE 每条事件全量重投影（O(N²)）
     + 前端时间线一次性渲染全部 nodes
     ↓
目标：
  ① 详情接口只返回 {run, nodes, todos}（去掉 events + context）
  ② events / context 懒加载（打开抽屉才拉）
  ③ 后端运行期全量+diff，SSE 推 node patch（node 级全量替换）
  ④ SSE 统一信封按 source 分流（evolution 推 patch，executor 推 event）
  ⑤ 终态发全量 snapshot 强制对齐
  ⑥ 前端删掉 projectTraceDetail，时间线改虚拟滚动
```

**技术栈变更**：前端引入 `react-window`（虚拟滚动）。后端新增投影 diff 逻辑（projector 本身不改，diff 在外层做）。

# 二、接口契约

## 阶段一改动的接口

### 1. evolution SSO 中间件（`app/core/sso_auth.py`）
- **改动**：`_verify_with_executor` 区分异常类型
  - executor 不可达（网络超时/连接拒绝）→ 返回 **503**（Response，不触发 401 跳转）
  - session 真失效（404/expired）→ 返回 **401**
  - 白名单不通过 → 返回 **403**（不变）
- **新增常量**：`SSO_UNAVAILABLE_STATUS = 503`

### 2. 前端 401/503 处理（`lib/api.ts`）
- **改动**：`_fetch` 底层拦截
  - `status === 401` → `onUnauthorized()`（去抖：500ms 窗口内多次只触发一次）
  - `status === 503` → **静默重试**（最多 3 次，指数退避 1s/2s/4s），不调 `onUnauthorized`
  - 其他不变
- **新增**：去抖机制（`_unauthorizedDebounce` 模块级变量）

### 3. Shell 守卫（`components/Shell.tsx`）
- **改动**：`fetchMeOrNull` 失败时重试 2 次（间隔 1s/2s），全部失败才 `navigate("/login")`
- **消除反弹**：登录页（`pages/login.tsx`）的 `fetchMeOrNull` 也加去抖，避免 Shell↔Login 互相反弹

### 4. Rust cookie 持久化（`src-tauri/src/state.rs` + `http.rs`）
- **改动**：`build_client` 改用 `cookie_store::CookieStore`（可序列化）+ `cookie_provider(Arc<jar>)`
- **新增**：启动时从 Tauri Store 反序列化 jar；登录成功后（响应含 Set-Cookie）序列化 jar 到 Store
- **改动**：`set_server_url` 切换服务器时清空持久化的 cookie

## 阶段二改动的接口

### 5. 详情接口 `GET /api/traces/{id}`（`app/view/traces.py`）
- **改动前**：`{run, events[], nodes[], context[], todos[]}`
- **改动后**：`{run, nodes[], todos[]}`（去掉 events + context）
- **同时修复**：`_reconstruct_incremental_inputs` 的 O(M×N) → 单次 O(N) 正向扫描建索引（即使 events 懒加载，重建逻辑仍被评分等场景使用，必须优化）

### 6. events 懒加载 `GET /api/traces/{id}/events`（新增）
- **入参**：`?event_ids=a,b,c`（逗号分隔，从 node.raw_event_ids 来）
- **出参**：`{events: TraceLogEvent[]}`
- **后端逻辑**：从 event_payloads 表按 event_id 批量查 + reconstruct_full_input（如有增量）

### 7. context 懒加载 `GET /api/traces/{id}/context`（新增）
- **入参**：`?anchor_id=xxx`
- **出参**：`{context: TraceContextSegment}`
- **后端逻辑**：从 nodes/context 表按 anchor_id 查单个 segment

### 8. SSE `GET /api/traces/{id}/stream`（`app/view/sse_stream.py`）
- **改动**：统一信封加 `source` 字段
  ```json
  {"_type": "data", "source": "evolution", "data": <node_patch>}
  {"_type": "data", "source": "executor", "data": <raw_event>}
  {"_type": "snapshot", "source": "evolution", "data": <nodes[]>}
  {"_type": "end", ...}
  {"_type": "error", ...}
  ```
- **evolution 源**：从 recorder.get_active_queue 消费 event → 全量投影 + diff → 推 node patch（节流 500ms）
- **executor 源**：保持现有 _poll_loop 拉 executor（不动）
- **终态**：推全量 snapshot（nodes 全量）

## 依赖关系
```
Phase 1：1.1 → 1.2 → 1.3（串行，后端先行）
          1.4（独立，可与 1.1-1.3 并行）

Phase 2：2.1 → 2.2/2.3（详情接口先行，懒加载接口依赖它定义）
          2.4 → 2.5（diff 引擎先行，SSE 推 patch 依赖它）
          2.5 → 2.6（SSE 推 patch 先行，前端收 patch 依赖它）
          2.6 → 2.7（前端收 patch 后，时间线才能改虚拟滚动）
          2.2/2.3 → 2.8（懒加载接口先行，抽屉才能用）
          2.9（独立，可任何时候做）
```

## 不改动的边界
- executor 认证端点（session 30 天滚动续期不变）
- 事件产生逻辑（middleware/截断阈值不变）
- SQLite 表结构（event_payloads/nodes 表不变）
- executor SSE 中继的数据拉取逻辑（保持拉 executor，只在信封加 source）
