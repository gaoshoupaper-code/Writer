## 已冻结决策（R1 共识）

- [x] **主路径**：路径 A · 增量嵌入（不重写 SKILL.md 结构，最小侵入）
- [x] **D1 快检输出**：**结构化表格**。8 项逐项扫，每项输出二值状态（✅/⚠️/N/A）+ 一句话说明。design 消费时一眼扫完。
- [x] **D2 排版原则**：**高密度低负荷**。决策点用单层表格（一行一选项 × 3 后果维度），每个格子放"结果 + 短因果链"（用 `→` 串）。推荐方案结论前置 + 一句理由。**默认极简，用户追问才展开推理链。**——摒弃"双层呈现"和"术语表"的过度设计，避免认知超载。
- [x] **D3 清单标识**：**固定标题字符串** `## § 实现风险清单`。design Step 0 按标题字符串扫描。简单、人机可读、零额外机制。

## 迭代修正（v2 · 用户反馈驱动）

用户实测后反馈："不是术语妨碍理解，是推理被省略"+"大脑处理能力有限，要一眼看懂又不要啰嗦"。

**Root Cause**：v1 的"双层呈现 + 术语表"违反认知科学——人的工作记忆 4±1 个组块，强制展开 6 段叙述 = 认知超载。错误地假设问题是"术语"，实际问题是"因果链被省略 + 信息密度配比错误"。

**修正方向（高密度低负荷）**：
- 删除 § 术语表（过度设计，解决错误问题）。
- 删除"学习层独立段落"（强制展开 = 强制超载）。
- 改造决策点模板：单层表格 + 每格"结果+短因果链"（`→` 串）+ 推荐方案结论前置。
- **AI 内部推演要全（覆盖所有要素），输出要精炼（高密度低负荷）**。
- 默认极简，按需展开——用户追问某选项细节才展开推理链。

> 这个迭代修正本身也是 § 实现风险清单的实战案例：用户实测暴露的"认知负荷"风险，在 v2 中被消解。

## 已冻结决策（R2 共识）

- [x] **D4 术语机制**：**SKILL.md 内术语表**。在 design SKILL.md 里维护一份高频术语词典（初期 10-20 词），AI 优先查表，查不到的临时解释并在下次复用。一致性与维护性的平衡点；词典渐进生长。
- [x] **D5 关键决策判据**：**三信号任一触发**——
  - (1) 会改变数据结构或接口契约
  - (2) 不可逆（上了就难回滚）
  - (3) 多选项间业务后果差异明显

## 已冻结决策（R3 共识）

- [x] **D6 术语表种子**：**AI 从 `docs/系统心智模型.md` 抽取 10-15 个项目高频术语**作为初始种子（harness / trace / evolution / executor / middleware 等），后续靠实战积累。
- [x] **D7 风险处理流程**：**写入+告知**。快检发现风险 → 直接写入 § 实现风险清单 → 当前轮提问里告知用户"发现 N 个风险，已记入清单"。不打断挖掘节奏。

**所有决策点（D1-D7）已冻结。**

### 改动 1：多轮挖掘循环里插入"可行性快检"环节

**位置**：`# Workflow → ## 多轮挖掘循环 → ④ 完善文档`之后，新增 `⑤ 可行性快检（关键决策触发）`。

**新增内容（草稿，待用户校准措辞）**：

```markdown
**⑤ 可行性快检（关键决策触发）**：

判断本轮是否冻结了"关键决策"——满足以下**任一信号**即触发：
- (1) 会改变数据结构或接口契约
- (2) 不可逆（上了就难回滚）
- (3) 多选项间业务后果差异明显

触发后，对刚冻结的决策跑一次**8 项 checklist 快检**（见下方"§ 可行性快检 checklist"）。

- 发现风险 → **直接写入** `## § 实现风险清单`，并在本轮提问里告知用户："本轮快检发现 N 个风险，已记入清单。"
- 无风险 → 不输出，保持节奏。

**职责边界**：快检只输出"风险点 + 在哪塌 + 建议验证方式"，**不展开 HOW**。HOW 是 design 的活。
```

每次关键决策冻结后，按以下 8 项座底 checklist 逐项扫描。输出为**结构化表格**：

| # | 检查项 | 状态 | 说明 |
|---|---|---|---|
| 1 | 数据结构 | ✅/⚠️/N/A | <一句话> |
| 2 | 外部依赖 | ✅/⚠️/N/A | <一句话> |
| 3 | 状态机 | ✅/⚠️/N/A | <一句话> |
| 4 | 并发与竞态 | ✅/⚠️/N/A | <一句话> |
| 5 | 错误路径 | ✅/⚠️/N/A | <一句话> |
| 6 | 权限与边界 | ✅/⚠️/N/A | <一句话> |
| 7 | 性能与规模 | ✅/⚠️/N/A | <一句话> |
| 8 | 部署与配置 | ✅/⚠️/N/A | <一句话> |

**状态说明**：✅ = 无风险；⚠️ = 有风险（写入 § 实现风险清单）；N/A = 不适用（注明原因）。
