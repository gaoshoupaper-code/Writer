# 进化端桌面侧栏重构

## 核心诉求

把桌面端左侧导航从当前的"扁平 13 项列表"重组为：
- **管理后台收敛为 1 个顶层导航项**（账户 / 积分 / 邀请码 / 积分设置等子项内嵌进去），仅超管可见
- **配置功能拆为 2 个顶层导航项**：① 进化端模型配置（现有 `/config`）；② 执行端配置（新建），仅超管可见

### 一句话概括
> 当前侧栏平铺直叙，管理后台 4 项跟基础导航混在一起，配置页又只管进化端 LLM。目标是用"收敛 + 拆分"让导航更清爽，并补齐执行端配置这个一直缺失的能力。

## 📌 需求基准总结（给产品负责人 A 角色看）

### 一句话
桌面端左侧导航做两件事：① 把超管的 4 个管理项收进一个"管理后台"父入口；② 把原"配置"页拆成"进化端模型"和"执行端模型"两个独立配置——因为评估和写作实际用的是不同模型，需要分开配。

### 改造前后对比

**侧栏项数量**
- 普通用户：9 项 → **8 项**（移除 `/config`，因为两个新配置项都仅超管可见）
- 超管：13 项 → **12 项**（基础 8 + 进化端模型 + 执行端模型 + 管理后台）

**超管侧栏新结构**
```
监测 / 历史 / 评估 / 进化 / Agent 要素 / 版本谱系 / 数据集 / 单次测试   ← 基础 8 项，不动
进化端模型 ⚙️                                                          ← 仅超管，含 App 更新检查
执行端模型 ⚙️                                                          ← 仅超管，新建
管理后台 🛡️                                                           ← 仅超管，进入后 tab 切换：
                                                                        用户 / 邀请码 / 积分流水 / 积分设置
```

**普通用户侧栏**：基础 8 项，看不到任何配置项和管理后台。

### 三个核心业务变化

1. **管理后台收敛**：原来平级的 4 个超管项（用户管理 / 邀请码 / 积分流水 / 积分设置）收进"管理后台"一个入口，进入后顶部 tab 切换。URL 仍是 `/admin/*` 各自独立（直链可用）。

2. **模型配置分家**：原来进化端 Agent 和 executor **共用一份**激活的 LLM 配置；现在拆成两份独立配置——
   - "进化端模型"：进化 Agent 做 evaluate/evolve 时用
   - "执行端模型"：executor 给用户写正文时用
   - 两边各自多厂商候选 + 单条激活，互不影响。

3. **数据迁移零风险**：现有生产环境的激活配置会**复制成两份**，一份归进化端、一份归执行端，上线那一刻两边都有配置可用，不会断服。

### 范围边界（不做什么）

- ❌ 不重排基础导航 8 项的顺序
- ❌ 不给普通用户补"我的积分"入口（记为下一期独立需求）
- ❌ 不引入折叠子菜单 / 页面内二级侧栏（保持扁平 + 顶层导航项的交互形态）
- ❌ 不动现有 4 个 admin 页面的业务功能（只改外壳：用 tab 包起来）

- 执行端模型配置的"App 更新检查"是否该挪到独立的"设置/关于"页（D22 暂留进化端模型壳页面）

## 🔴 关键矛盾：执行端配置的"归属"和"链路"对不上

> **R4 已解决**：查证后确认 evolution 现有 `llm_configs` 表 + `/api/config/llm*` API + executor `/api/ingestion/active-key` 拉取链路，**进化端 Agent 和 executor 当前共用同一份激活配置**。决议 D14：同表加 `scope` 字段分家。

### 查证事实（带来源，事实非决策）

- **表**：`evolution/app/core/db.py:345-355` —— `llm_configs` 表，字段 `id/name/api_key_enc/base_url/model/is_active/created_at/updated_at`，AES-256-GCM 加密
- **进化端 CRUD API**：`evolution/app/config/api.py:7-13,96-173` —— `/api/config/llm*`（list/create/update/delete/activate/test），桌面端 `api.ts:222-325` 已对接
- **executor 拉取链路**：`executor/app/platform/llm_config/loader.py:95-117` —— `GET /api/ingestion/active-key`（进化端实现 `evolution/app/ingestion/ingestion.py:181-204`），60s TTL 缓存，明文三元组，`X-Notify-Token` 内网鉴权
- **进化端自消费**：`evolution/app/common/model_factory.py:65`、`evolution/app/core/llm.py:23` 也读同一份激活配置
- **结论**：一份配置两边共用，激活全局唯一
