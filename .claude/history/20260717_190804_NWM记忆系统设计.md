# NWM 记忆系统改造 · 技术设计

> **需求来源**：`.claude/md/20260717_171954_NWM记忆系统优化.md`（status: confirmed）
> **设计性质**：在现有 Graphiti+FalkorDB 骨架上补齐 NWM 论文精髓，修已知 bug，新增 recall_memory 工具 + 世界状态快照 API + trace 扩展。**补齐而非重构。**

## 0. 技术调研发现（设计前置约束）

调研已覆盖 Graphiti 0.19.10 的 API 能力 + Writer 前后端挂载点。以下为**被代码卡死、无选择空间**的约束：

| # | 约束 | 代码依据 | 设计影响 |
|---|------|---------|---------|
| C1 | **causal_cutoff bug 比预期严重**：`SearchFilters(max_date=...)` 在 graphiti 0.19.10 根本不存在该字段，pydantic 会忽略额外字段 | `graphiti_core_falkordb/search/search_filters.py:40-50`（字段列表无 max_date） | 因果截止必须改用 `SearchFilters(valid_at=[[DateFilter(date, ComparisonOperator.less_than_equal)]])`，**不是简单传参** |
| C2 | **Graphiti 无"按属性批量 invalidate 边"的 API** | `graphiti.py:1004-1037` `remove_episode` 只接 uuid | 幂等去重链路：查 episode name → 拿 uuid → remove_episode → 重 add_episode |
| C3 | **episode 无 metadata 字段** | `graphiti.py:349-364` add_episode 签名锁定 | source_chapter 盖戳只能走 name/source_description/节点 attributes |
| C4 | **backend.retrieve 支持 causal_cutoff 参数，但 middleware 从未传** | `backend.py:71-79` 有参数 vs `memory_recall_middleware.py:123-128` 未传 | 改一行即可（在 C1 修复基础上） |
| C5 | **TraceMemoryQuality 加字段天然向后兼容**（pydantic + 全字段 default） | `contracts/trace/__init__.py:47-61` | 无需迁移 |
| C6 | **前端加 panel 需改 6 处**，有 storyline panel 完整范例 | `desktop/src/components/workspace/StorylinePanel.tsx`（168 行参考） | 模式可复用 |

### 核心设计哲学（承自需求）

- **图谱对作者黑盒**：world-state API 返回叙事化文本，不暴露节点/边标签
- **叠加非替换**：middleware 注入 + 工具深挖，ContextAssemblerMiddleware 保留作 fallback
- **可进化优先**：recall_memory 工具 + query 构造 + schema 都在 harness 包

## 2. 已确认决策（R1）

| # | 决策点 | 选择 | 设计含义 |
|---|-------|------|---------|
| S1 | recall_memory intent 枚举 | **B. 先开 3 类**（latest_state/relationship/promise_payoff） | 用现有 schema 能力支撑；knowledge_boundary/object_location/temporal_order 留 evolution 在 schema 补全后开 |
| S2 | 世界状态快照存储 | **B. 入图时写盘缓存** | 复用 StorylineGraphData 模式（写 `workspace/world_state/chapter-N.json` + mtime stale 检查）；入图流程内顺带生成；API 只读文件 |
| S3 | 幂等去重存储键 | **A. 查图谱 episode name** | `EpisodicNode.get_by_group_ids` 过滤 `name == chapter-{N:02d}`；单一真源在图谱；统一 name 零填充格式 |

### 决策副作用（必须在数据模型轮敲定）

- **S2 断层**：快照生成挂入图流程 → 需定义"主次角色判定"算法 + 快照生成失败时入图是否回滚
- **S3 断层**：remove_episode 删"只被该 episode 引用的节点" → 需明确这是预期行为（章节重写后角色可能消失）
- **S1 断层**：3 类 intent 的查询实现各需哪些 Cypher / Graphiti API → 需在接口契约轮细化

## 3. 已确认决策（R2 数据模型）

| # | 决策点 | 选择 | 设计含义 |
|---|-------|------|---------|
| S4 | 主次角色判定算法 | **C. 混合**：主角（有 BELONGS_TO_THREAD）必进 + 配角按 PARTICIPATES_IN 次数 Top-N（默认 N=10，可配） | Cypher 查询两段：先 MATCH Thread 归属角色，再 MATCH 按事件参与度排序取 Top-N；N 可配置（evolution 后期可调） |
| S5 | 快照生成失败语义 | **B. 容错跳过**：日志告警，入图继续；API 侧 fallback 实时 Cypher 查 | 快照是派生产物，不阻塞主流程；API 侧复用 StorylineGraphData 的 is_stale 模式，缓存缺失/异常时实时查 |
| S6 | source_chapter 戳粒度 | **C2. 增量补全**：新章节带戳 + 旧节点反查 episode | schema 加字段；新入图节点带 first/last；旧节点 source_chapter 留空或反查 episode name；零数据迁移 |
| S6-sub | source_chapter 语义 | **C. 两字段都存**：first_appearance + last_referenced | 对齐 NWM 论文 Character state schema；抽取逻辑：节点不存在→新建(first=last=当前章)，存在→只更新 last；trace 用 first_appearance，快照用 last_referenced |

### 数据模型变更清单（S4-S6 落地）

**narrative_schema.py（harness 可进化）**：
- CharacterEntity.attributes 加两个字段：`first_appearance: int`、`last_referenced: int`
- LocationEntity / ThreadEntity / StoryNodeEntity 等同加（统一盖戳）

**节点 attributes 写入逻辑（backend.py ingest 时）**：
```python
# 伪代码：add_episode 后处理抽取出的节点
for node in extracted_nodes:
    existing = find_node_by_name(group_id, node.name)
    if existing is None:
        node.attributes["first_appearance"] = chapter_index
        node.attributes["last_referenced"] = chapter_index
    else:
        existing.attributes["last_referenced"] = chapter_index
        # first_appearance 不动
```

**主次角色判定 Cypher（snapshot.py 用）**：
```cypher
// 主角：挂 Thread 归属
MATCH (c:Character)-[:BELONGS_TO_THREAD]->(t:Thread)
WHERE c.group_id = $gid AND c.last_referenced <= $chapter
RETURN c

// 配角：按事件参与度排序
MATCH (c:Character)-[p:PARTICIPATES_IN]->(s:StoryNode)
WHERE c.group_id = $gid AND c.last_referenced <= $chapter
WITH c, count(p) AS participation
ORDER BY participation DESC
LIMIT $top_n
RETURN c
```
