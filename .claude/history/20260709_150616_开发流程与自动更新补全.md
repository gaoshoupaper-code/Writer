# 需求：后续开发流程决策 + 写作端自动更新 UI 补全

## 核心诉求

两个独立子需求：

1. **开发流程咨询**（非编码任务）：用户在"每次改完上传服务器看效果"和"本地搭一套开发环境"之间犹豫，想知道哪种后续开发方式更省事，以及现在再弄本地环境是否麻烦。
2. **写作端自动更新 UI 补全**（编码任务）：进化端已有完整自动更新 UI（`UpdateBanner.tsx`），写作端 Rust 后端能力齐全但前端零消费，需要补齐前端入口使其可用。

---

## 现状基线（已核实，非推测）

### 自动更新（子需求 2）
- 两端 Rust 后端能力完全一致：`tauri-plugin-updater` 插件 + `updater.rs`（check_update / install_update / check_on_startup）+ lib.rs 注册 + tauri.conf updater 配置 + 同一把签名公钥。
- 进化端：`evolution/desktop/src/components/UpdateBanner.tsx`（73 行）+ Shell.tsx 挂载 → 完整可用。
- 写作端：`desktop/src/` 下 grep `update_available`/`check_update`/`install_update`/`UpdateBanner` 零命中 → 前端无任何入口。
- endpoint：写作端 `https://siyen.site/releases/latest.json`，进化端 `latest-evo.json`。
- 发布：本地脚本 `scripts/publish.sh` / `publish-evolution.sh`（tauri build → 签名 → latest.json → scp 上传服务器），无 CI/CD。

### 开发流程（子需求 1）
- 架构：Docker Compose 单机（nginx + executor:7788 + evolution:7789 + website）部署在 `siyen.site`（111.228.4.165:22222）。
- 桌面端 dev：`npm run tauri dev`，连本地后端（写作端 1420 → 7788，进化端 1421 → 7789）。
- 本地后端：executor/evolution 各有 `.venv` + `.env`，uvicorn --reload 跑。
- 本地启动脚本：`start-dev.ps1` / `start-all.ps1`。
- 发布脚本：`deploy-prod.sh`（5 Phase 一键部署，需 root + 服务器）。
