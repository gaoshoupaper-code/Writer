# 进化端桌面 / 记忆要素对齐 需求

## 核心诉求（待用户确认）

创作端 Agent 在 NWM 记忆系统重构（commit 25de1a6）后，harness 包新增了 6 个记忆相关要素：
- `tools/`: narrative_schema / query_builder / join_rules / packet_formatter（4 个 NWM 可进化工具）
- `middleware/`: memory_recall_middleware（检索回填）
- `prompts/`: memory_extraction_guide（抽取提示词）

进化端（桌面 UI + 进化 Agent 认知 + 评估 Agent 维度）目前都没有同步反映这套新要素，
存在 3 个断层。本次需求要把进化端对齐到能认知/评估/观测记忆系统。

**关键约束**：记忆要素是分散在现有 prompts/middleware/tools 目录下的（不是新增 memory/ 目录），
所以进化 Agent 的"写工具"层面已经能改它们，真正缺的是认知 + 观测 + 评估。

## 现状事实（调研所得）

### 创作端要素（harnesses/repo/）
- prompts/ 含 memory_extraction_guide.md
- middleware/ 含 memory_recall_middleware.py
- tools/ 含 4 个 NWM 可进化工具（narrative_schema/query_builder/join_rules/packet_formatter）
- assemble 入口 __init__.py 里有 _build_memory_recall_middleware，按 ctx 条件注入

### 进化端认知断层
1. **进化 Agent system prompt**（evolve/agent/prompt.py）：
   ③段"要素全景"写"八要素"（prompts/middleware/tool/subagents/skills/assemble + State），
   完全没提记忆系统，Agent 不知道这 6 个要素是啥、改了影响什么。
2. **评估 Agent prompt**（eval_agent/prompt.py）：
   四维度（协作拓扑/错误保障/资源消耗/内容质量），无记忆一致性/检索质量维度。
3. **桌面端 evolution/desktop**：
   harness-constants.ts 只定义 6 hook + 6 agent 角色；harness tab 按 agent/hook 分组，
   没有记忆运行可视化。Phase 4 已埋点 trace run_meta（记忆质量事件），桌面未消费。

但若 prompt 不认知 + 评估不诊断，进化闭环是断的。

## 已确认决策（R2）

### D4. 运行时质量展示位置 = trace 链路视图里嵌
不新开 Tab、不进 monitor 首屏。把 memory_quality run_meta 事件作为 trace 链路里的
一个节点/折叠区，点开看该次检索的 hits/token/causal_cutoff/截断/错误。
理由：运行时质量属 trace 维度（每次检索是一次事件），和 harness 静态配置是两个维度，
最自然的位置是 trace 链路视图，让"执行上下文 + 记忆召回"在一起看。
（D2 的"融入 harness 分组"专指静态要素源码的分组标识，不冲突。）

### D5. 评估 Agent 新增"记忆"维度，评估 4 类现象（全选）
1. **检索失败率/降级频次**：run_meta 里 ok=false / error 非空的比例。
   高失败率 = middleware 降级频发（D-R5-1 兜底被频繁触发）。
2. **检索命中质量（空召回/低命中）**：hits 为空或 stage1_count=0 的比例。
   检索不出东西 = query_builder 或 extraction 有问题。
3. **packet 截断频次**：truncated=true 的比例。频繁截断 = packet 太大/查询太宽，
   可能 join_rules 或 packet_formatter 需优化。
4. **抽取覆盖率（记忆条目跨章分布）**：跨章看 source_chapter 分布。
   后面章节检索老只命中开头 = 抽取遗漏（extraction_guide 或 schema 有洞）。
   这是 NWM 论文核心价值点（因果锚点）。
证据源全部来自 Phase 4 已埋点的 run_meta 事件，不需额外埋点。

### D6. 进化 Agent prompt 呈现 = 单独"记忆子系统"节
在③段"要素全景"里单独加一节，说明 6 个要素怎么协同
（抽取 extraction_guide → 存储 narrative_schema → 检索 query_builder+join_rules+
packet_formatter → 回填 memory_recall_middleware）+ 改每个的影响。
让 Agent 把记忆当整体理解，而不是 6 个零散文件。

## 已确认决策（R3）

### D7. 桌面静态要素标识形态 = 顶部集中卡片（设计阶段修订）
~~原 D7：徽章 + 筛选~~。随 D2 修订为集中卡片方案：harness 页顶部"记忆子系统"卡片，
集中展示 6 要素（各带名称/路径/作用），不再用徽章+筛选模式。

### D8. eval vs reflection 职责边界 = eval 单次 / reflection 跨次
- **eval**（本次新增记忆维度）：评**单 trace**，现时诊断打分。
- **reflection**（已存在）：跨 trace 归纳失败模式库，给进化 Agent 参考。
- **现象命名对齐**：eval 发现的现象与 reflection 已归纳的模式名字保持一致
  （recall_miss / retrieval_fail / truncation / extraction_gap），但职责不重叠。

### D9. 记忆维度 severity = 复用现有规则
沿用现有 eval prompt 的 severity 锦点：
- **high 可单点成立**（如检索持续失败导致写作降级）
- **medium / low 需 ≥2 处独立证据**
不单独给记忆维度定阈值，保持与其他维度 severity 风格一致。

### D10. 验收标准（4 项全要）
1. **桌面静态要素可识别**（设计阶段修订）：harness 页顶部"记忆子系统"卡片展示全部
   6 个记忆要素（名称/路径/作用 + 协同关系）。验证：打开任一版本 harness 页，顶部可见
   记忆卡片，6 要素齐全。
2. **桌面 trace 可看记忆召回**：trace 链路视图里，每次记忆检索的 run_meta 事件能作为
   节点/折叠区展示，点开看 hits/token/causal_cutoff/截断/错误。
3. **进化 Agent 能认知记忆要素**：读 prompt 后能说出记忆 6 要素是什么、改 query_builder
   会影响检索一致性。
4. **评估 Agent 能诊断记忆**：对一条 trace 能输出 dimension=记忆 的 findings
   （含 4 类现象 + severity）。

### D11. 分期交付 = 两期
- **第一期**：桌面静态要素可识别（D10-1）+ 进化 Agent 认知（D10-3）。
  不动数据消费，改动集中在桌面徽章 + evolve/agent/prompt.py。
- **第二期**：桌面 trace 记忆召回（D10-2）+ 评估 Agent 维度（D10-4）。
  集中处理 run_meta 展示 + eval prompt 记忆维度。
